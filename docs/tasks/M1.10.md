- **Lessons:**
  - The ticket scope still says "`node:http` router"; revision 3 replaced it with Hono. Follow the revision-3 bullet at the end of the scope, not the first bullet.
  - The spec contract changed under a ticket in flight: M1.01 merged new route names (`POST /v1/pairing`, `/v1/pairing/revoke`), `credential_not_allowed`, a `501` commands stub, and persistent pairings while M1.10 was being built to the old contract. Re-read the contracts after every rebase, before review, not only at start.
  - A route that mints pairing codes over HTTP, even behind the CLI token, would reopen the self-approval hole, because the agent can read that token. Minting stays in-process (`PairingStore.issueCode()`), and a test asserts no such route exists.
  - Hono middleware registered with `app.use()` in `createApp` also guards routes other modules add to the returned app later, so later tickets inherit the Host, Origin, and credential checks. A test adds a route after `createApp` to prove it.
  - `@hono/node-server` falls back to its own `hostname` option when a request has no Host header, so the Host check must read the header, not the request URL.
  - A synchronous `openSync` on a FIFO blocks the whole Vitest worker, so a per-test timeout cannot fire; the red run for that case had to be killed by hand. Open untrusted paths with `O_NONBLOCK` before `fstat`.
