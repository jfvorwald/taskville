## For the lead and #16

- **`bootEngine` now requires `pairing`**, the same `PairingStore` passed to `createApp`, so `taskville unpair` ends browser streams. No caller on main yet; `serve` (#16) must pass it. Optional `maxStreams` and `drainTimeoutMs` default to 64 and 5,000 ms; `engine.maxStreams` and `engine.drainTimeoutMs` report them.
- A stalled reader during the **backlog** phase (before it is live) is not cut off: frames are paged from storage, so memory stays bounded, and the 64-stream cap bounds sockets. A write timeout for that phase was not asked for here.

## Lessons

- A timer started after `await subscriber.run()` never runs for the case it exists for: the pump is itself blocked on a write to the stalled client. The bounded wait has to start at the cut-off, inside the subscriber.
- Ordering of cheap policy checks matters for safety, not only speed: putting the producer policy first removed the only reachable path to unbounded nesting, and the `RangeError` catch is the backstop.
