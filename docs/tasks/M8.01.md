- **Review fixes:**
  - Commits come from `rev-list --branches --tags --remotes HEAD`; HEAD is added only when `rev-parse --verify --quiet HEAD^{commit}` resolves (not unborn).
  - Ref events only for `refs/heads/*` and `refs/tags/*`; remote-tracking and symbolic refs are read, skipped and counted.
  - `git log` records are framed by a leading NUL (`%x00`), not U+001E; only SHAs requested in the batch are accepted and a repeated SHA is ignored. The committer date no longer comes from `git log`.
  - `sourceId` is `git:<sha256(realpath) first 16 hex>`, the watcher's scheme (`shortHash`).
  - Failures throw `not_a_repository`, `git_timeout`, `git_output_too_large` (or `git_failed` for any other git error); never a path, stderr or argv. Abort still rejects with the AbortError.
  - A log batch that overflows the output cap is halved and retried (down to one commit).
  - `--no-replace-objects` on every call.
  - Pre-1970 commits import: git prints a negative date as an unsigned 64-bit number (and `git log %ct` prints nothing), so dates come from `rev-list --timestamp` and `for-each-ref`, and values of 2^63 or more are read as negative. The sane-range guard (12 digits) is kept.
  - `createGitImporter({ batchSize?, maxOutputBytes?, timeoutMs? })` is exported next to `gitImporter`. Import default timeout is 60 s per git call (the watcher keeps 10 s); the output cap is the watcher's 16 MiB.

A single commit whose log output alone exceeds the cap also fails with `git_output_too_large`. Merge commits omit `files`.
