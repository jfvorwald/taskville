## What is masked now

- **Names** (`isSensitiveName`, used by assignments, `--flags` and JSON keys): the last word ends in `password` with nothing in front (`PGPASSWORD`); `pass` or `pwd` as the last word with a qualifier in front (`DB_PASS`, `SMTP_PASS`, `REDIS_PASS`, `MYSQL_PWD`); `SECRET_KEY_BASE`. A bare `PWD` (the shell's working directory) and a bare `pass` (a test counter, `{"pass": 12}`) are deliberately not sensitive. A side effect: `test_pass` or `isPass` count as sensitive names, so a JSON number under them is sealed.
- **Short `-p`** (text), only after these commands, up to a newline, `;`, `&` or `|`:
  - `mysql`, `mysqldump`: attached `-pSECRET` only. A bare `-p` prompts and the next word is the database.
  - `sshpass`: `-p SECRET` or `-pSECRET`. Options end at the first word that is not one (`-f`, `-d` and `-P` take an argument), so the `ssh -p 2222` it runs keeps its port.
  - `docker` or `podman`: global options are not parsed. If the command (up to a newline, `;`, `&`, `|` or a backtick) has a whole `login` word after `docker`, every `-p SECRET`, `-pSECRET`, `--password SECRET` and `--password=SECRET` in it is masked, with no limit on words. `docker run -p 8080:80 img` has no `login` and stays readable. `docker run -p 8080:80 img login` is masked (`8080:80` becomes a marker): an accepted over-mask, pinned by a test.
  - A complete reference (`-p"$DB_PASS"`, `-p $TOKEN`) or an existing marker stays readable. Quotes wrapping the whole password are left out of the mask; an unquoted backslash escapes the next character, so `-pfoo\ bar` is one word.
- **Pairs.** In `redactJson`, the `value` next to a sensitive `name` or `key` (any case) is sealed like a sensitive property: a string, number, boolean, object or array becomes one marker; `null` and a reference stay. In text, `{"name": "DB_PASSWORD", "value": ...}` is masked in either order, across line breaks, with a string, number, object or array value of any length. A `name` and `value` with another property between them are not matched as text; they are in `redactJson`.
- **Bounds.** A name-first value that never closes is masked to the end of the text, which is paid once. A value-first pair must close exactly where the comma before the name sits, so a name nested inside the value does not end it early. Candidates are tried against a work budget of 500,000 characters per call; past it, the text from the first `"value"` in the text up to the name is masked (over-masking, never a leak; an outer value that holds an earlier name starts before it).
- **Shared fix:** `shellWordEnd` now honors a backslash outside quotes. It also applies to the `curl -u` rule, which can now mask a few more characters after an escaped separator; every existing test passes unchanged.

## Old events and the dedupe hash

Masking changes the content hash of an affected event, as in M2.17: the hash is over the masked payload. Events already in the log keep what they stored, which for the F2 shapes is the unmasked text; this ticket does not rewrite them. If the same hook is retried after the upgrade (for example a spooled hook replayed), it masks differently from the stored copy, so it is a `conflict` instead of a `duplicate`. Only events whose `tool_call.started.summary` or another free-text field held one of the F2 shapes can change. Evidence bodies are keyed by content hash and written once per tool call and part, so a retry keeps the first write.

## Lessons

- A password flag has to be tied to its command and to that command's own option parsing: `-p` is a port in ssh, psql and `docker run`, and `sshpass` runs another command whose own `-p` must stay readable.
- A text rule for a pair must be written for both property orders, line breaks, and values of any size, and its cost must not depend on the order: scan forward from a name (an unclosed value masks to the end, paid once), but back from a name only to a value that closes exactly at the comma, with a budget and over-masking as the fallback.
- Each rule that reads a value needs its own idempotency check: a sealed number leaves `"value":[REDACTED:...]`, and the loose value end cuts at the `]` inside the marker.
- Do not parse another tool's option grammar when a coarse rule over-masks safely: a bounded word-walk over `docker` global options leaked at the limit and was quadratic on a crafted word, and took three review rounds. A segment that contains `login` is linear and cannot be outrun.
- A window limit on a scan is a bypass if the text is attacker-shaped. Either scan to the real boundary or mask more, never less.
