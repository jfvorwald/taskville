## Behavior

- **Claiming.** The engine takes the shim's mkdir lock (`claude-code.lock`, PID inside). It waits at most 2 s, and breaks a stale lock under `claude-code.lock.break` by the shim's own rule. Under the lock it renames `claude-code.jsonl` to `claude-code.replay-<uuid>.jsonl`. Shim appends during replay then start a fresh main file, which is never touched (test "keeps a line the shim appends during replay"). If a live shim holds the lock past the wait, the main file is left (`mainFile: "busy"`) and the drain retries it.
- **Reading.** The engine reads that file and every `claude-code.<id>.jsonl`, oldest mtime first. Files that are not regular or not owned by this user are never followed or read. Lines over 5 MiB + 64 KiB are discarded without being buffered. Each line must have exactly the shim's keys, read with `Object.hasOwn` (so `__proto__` is just an unknown key). `sourceEventId` is at most 170 characters and `spooledAt` must be a protocol timestamp.
- **Skipped lines.** Unparseable or malformed lines are counted (`invalidLines`) and never logged. The oversized marker (`payload: null`, `payloadBytesAtLeast`) is **skipped** and counted as `oversized`, since there is nothing to map. Recording it would need a new event type.
- **Replay.** Each hook goes through `ClaudeCodeSource.ingestHook({ sourceEventId, payload, late: true, receivedAt: spooledAt })`, so `occurredAt` is when the hook ran. The batch is ordered by `spooledAt` (`compareTimestamps`). Within one run that order holds; across bounded runs, ingest order follows ARCHITECTURE 7.3. Late requests are stored expired, so they never open needs-you. A hook posted live and then spooled after a shim timeout dedupes to `duplicate`.
- **Crash safety.** A file is deleted only after every hook read from it committed. A partly read file records the next line's byte offset in `<file>.offset`, written after commit. If an ingest throws, the run stops and keeps everything (`failed`). Any crash re-reads at worst some lines, and they dedupe on `sourceEventId`. Orphan offsets are removed.
- **Poison hooks.** If a hook's ingest throws, the run stops and keeps its files. The failure is counted per `sourceEventId` in `claude-code.attempts.json`, across runs. On the 3rd failure (`MAX_HOOK_ATTEMPTS`), the hook is appended in the shim's line format to `claude-code.poison.jsonl` (0600; created without following a symlink and only appended to when it is this user's regular file) and counted as `poisoned`. Only the error name is logged, and the run continues, so the lines after it replay (test "quarantines a hook that fails 3 times across runs"). If the poison file cannot be written, the hook stays in the spool. A quarantined hook stays marked, and is skipped, until a run that read it completes. That way a later failure, which keeps the spool, never sends it back for another 3 tries (roborev 5212; test "never retries a quarantined hook when a later hook fails"). A success clears the hook's count, and the attempts file is removed once nothing is pending. The poison file is never replayed.
- **Bound.** One run takes at most 2,000 hooks or 64 MiB, about 3 s at the measured rate. `serve` runs one bounded `replaySpool` after registering config projects and before listen. If work remains, `drainSpool` continues in bounded runs after listen, 250 ms apart. It stops after 5 idle runs and is aborted and awaited at shutdown.
- **Cleanup.** At start, the engine removes a `claude-code.lock.break` older than a minute (left by a killed shim; M2.01 risk 2) and shim or engine temporaries (`.claude-code.*`) older than a minute.

## UUID-only sourceEventId (lead addition, roborev 5161 on M2.04)

The mappers build event and request IDs from the shim's `sourceEventId` without masking them, so a secret-shaped ID would land in the log as is. The hooks route now accepts only a lowercase UUID v4 (`SHIM_SOURCE_EVENT_ID`, exactly what the shim generates) and refuses anything else with 400 `bad_request`. That covers uppercase, other UUID versions and variants, no dashes, braces, surrounding whitespace, a trailing newline, the old 170-character strings, and `ghp_` strings. The spool replay skips such a line as invalid, counted and never logged. Existing route and fixture tests now post shim-shaped IDs through `hookId(label)` in the test helpers.
