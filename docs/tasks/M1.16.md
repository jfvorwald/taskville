## Commands

- `taskville demo run --offline --seed <n> --duration <sim-time> [--pace calm|lively|change=...] [--json]`: prints `seed · pace · duration · events` and `stateHash <hash>` from `runOffline`; `--json` prints `{ seed, pace, durationMs, events, stateHash }`. `--offline` is required (cli.md lists it).
- `taskville demo start --project <id> --seed <n> [--pace ...] [--speed <x>] [--duration <sim-time>]`: `runProducer` with `startAtMs: Date.now()`, `now: Date.now`, an abortable `setTimeout` sleep, `stop` on SIGINT, and `post` through the CLI token's `POST /v1/events/batch`. Prints the run line, then `steps · events · accepted / duplicate`. Exit 0 when the duration ends or on SIGINT; 2 for an unknown project; 3 unreachable and 5 auth from the shared client; 1 for any other rejected demo event (cli.md names no code for it) and for usage errors.
- Validation: `--seed` a safe integer; `--duration` a positive finite duration (`s`, `m`, `h`); `--speed` a finite number above zero; pace intervals finite.

## Follow-ups for the lead

- `packages/demo` `parsePace` and `parseDuration` accept numbers that overflow to `Infinity` (M1.15). The CLI now refuses them, but other callers would not; a small fix there (reject non-finite results) belongs to a demo-package ticket.

## Lessons

- Any parsed number that drives a loop or a clock needs a finiteness check: `Number("9".repeat(400))` is `Infinity`, which a regex for digits happily accepts. The review found it three times (duration, pace, speed), one flag at a time.
- `timeout` is not on macOS; a hang-prone red run needs another guard (a worker with a deadline), or should not be run at all.
