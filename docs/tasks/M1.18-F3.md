## What changed

All in `packages/adapters/src/redact/text.ts`, with rows in `packages/adapters/test/redact.test.ts`.

- **Any Authorization scheme** (kind `bearer-token`): `Authorization` or `Proxy-Authorization`, then `:` or `=`, a scheme word and a credential of 8+ characters. After a known scheme (Token, ApiKey, Bearer, Basic, Digest, Negotiate, NTLM, OAuth, Hawk, SSWS, DPoP, MAC, AWS4-HMAC-SHA256, ...) any such credential is masked, letters-only included. After an unknown word the credential needs a digit or 16+ mixed-case characters, so `Authorization: handled internally` stays readable.
- **Parameterized schemes** (kind `bearer-token`): when the scheme is followed by `name=value` (Digest, AWS SigV4, OAuth 1.0, Rails `Token token="..."`), everything from the first parameter to the line end is masked. The list is not parsed, so escaped quotes, spaces around `=`, or long values cannot end the mask early. A token68 credential with `=` padding (`Basic dXNlcjpw==`) is not taken for a parameter list: the character after `=` must start a value, and an empty or space-led quoted value (`a="",`, `a=" x",`) counts only when a comma follows it.
- **curl user credentials** (kind `basic-auth`): `-u user:pass`, `-uuser:pass`, `--user user:pass`, `--user=user:pass`, `-U` and `--proxy-user`. Only the password is masked, as `url-password` does for URLs. The value is read as one shell word: adjacent quoted and unquoted segments joined (`"$API_USER"suffix:pass`), complete references taken whole, and the password is everything after the first colon, with wrapping quotes dropped. Not masked: no colon (within 128 characters), an empty password (`-u admin:`, curl prompts), or a password that is one complete reference (`$API_TOKEN`, `$(id -g)`). A `-u` inside a readable command substitution is read too (`-u $(curl -u admin:pass ...)`).
- **Linear time:** each Authorization header masks to its line end once, skipping later matches inside it; flags inside an already masked password are skipped. 18 new adversarial inputs cover repeated headers, unterminated and escaped quotes, flag chains and long users and passwords.
- **TOKEN_PATTERNS** entries can carry an `accept(match)` predicate for patterns that also match prose.

## Accepted false positives

Masking errs toward hiding, so these are masked although they are not secrets:

- `docker run -u 1000:1000` and `-u user:group` mask the group; `rsync -u host:/srv` masks the path; `git add -u :/` masks `/`. Earlier versions of this PR exempted numeric pairs and `/` or `~` paths; roborev showed each exemption also hid a real password (`curl -u 1000:123456`, `curl -u admin:/secret123`), and a command-aware exemption would be more bypass surface.
- A curl command with a parameterized Authorization header masks the rest of the line, including the URL after the header.
- `Authorization: Token required` and similar prose after a known scheme word, and letters-only placeholders such as `Authorization: Token xxxxxxxx`.
- Already masked before this change and left alone (M1.20 behavior, quoted values under a sensitive name): `headers.authorization = "Token " + token;` masks `Token `.

## Notes for the lead

- Six review rounds found 18 cases. Each was a new shape, apart from the space-led Digest value (fixed twice, in 1b544da and 8aa4372). The rounds converged once the parsers stopped trying to be precise: the Authorization rule masks to the line end, and the curl rule reads one shell word. If another post-commit round finds a new shape, the shape-by-shape approach has reached its limit. The next step would be a decision on masking the whole line after any `Authorization` header or `-u` flag.

## Lessons

- The M1.20 lesson held again: every exemption drew a finding. The path and numeric-pair exemptions for `-u` each looked safe with the realistic examples in hand (`rsync -u host:/path`, `docker run -u 1000:1000`), and each hid a real password in another command. For a redactor, a harmless false positive is the cheaper error.
- Parsing a credential-bearing syntax precisely (Digest parameter lists, shell quoting) gives reviewers an endless supply of edge cases: escaped quotes, spaces around `=`, empty values, length budgets. Masking to a robust boundary (the line end, the end of the shell word) closed whole classes at once. Pick the coarse boundary first and refine only where false positives hurt.
- Skip-ahead guards that keep a scanner linear can hide nested input: skipping every flag inside an earlier flag's word missed `-u $(curl -u admin:pass ...)`. Skipping only inside regions already masked is safe, because those regions are hidden anyway.
- A test that asserts the secret text is absent breaks when the secret equals text that should stay (`admin:admin` keeps the user `admin`); such cases need an exact-output assertion instead.
