### Sync rules

1. `GET /v1/projects/:id/snapshot` with `X-Taskville-Session`, validated with `snapshotResponseSchema`; the state is loaded into the store at its cursor.
2. `GET /v1/projects/:id/events?after=<store cursor>`; each `event` frame goes through the domain `reduce`. A frame with `id <= cursor` is skipped (duplicate). `id > cursor + 1` (gap), a `resnapshot` frame, an unparseable frame, or a reducer error means a new snapshot, then a new stream from its cursor.
3. Stream ends or errors: connection becomes `stale`, the last view is kept, retry with backoff (0, 0.5 s, 1 s ... 15 s) from the store's own cursor (no new snapshot, so resume is gap-free). Backoff resets once a stream opens.
4. Before the first snapshot the connection stays `connecting` (there is no view to call stale).
5. No retry on: 401 (`unauthorized`), 404 (`unknown_project`), reducer version differs from this build (`reducer_mismatch`), snapshot that fails validation (`bad_response`). The connection becomes `failed` with `error` set; the last view stays.

### Store shape (the interface other tickets use)

```ts
interface DataState {
  projectId: string | null;
  state: ProjectState | null;        // reducer state; null until the first snapshot
  cursor: number;                    // last applied ingest sequence
  connection: "connecting" | "live" | "stale" | "failed";
  error: "unauthorized" | "unknown_project" | "reducer_mismatch" | "bad_response" | null;
  agents: readonly Agent[];          // registration order
  attention: readonly Attention[];   // most urgent first
  counts: { needsYou; trouble; waiting };  // header counts
  selectedAgentId: string | null;    // navigation
  select(agentId | null): void;
  refreshAttention(): void;          // recompute time-based attention (silence) from the clock
  // sync-loop only: reset, applySnapshotState, applyEvent, setConnection, fail
}
```

`agents`, `attention` and `counts` keep their reference when their inputs are unchanged, so `useData((s) => s.agents)` does not re-render on unrelated events. A resnapshot keeps `selectedAgentId`; `reset(projectId)` clears it.
