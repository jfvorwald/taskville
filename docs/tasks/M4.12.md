- **Lessons:** the probes came from the T3 Code desktop app (traced with `lsof` to its process), which polls new local ports. Tests that count requests on a local stand-in server must ignore foreign clients. Not a shim race and not a token leak: removing `--noproxy '*'` from the shim still fails the proxy test.

## Root cause

The shim tests start stand-in HTTP servers on ephemeral loopback ports and assert exact request counts. T3 Code probes newly opened local ports with `GET /`. A probe during a test added an entry to `server.received` (5 instead of 4), an entry to `proxy.received` (length 1 instead of 0), or an empty body that made `JSON.parse("")` throw. The earlier hypotheses (late requests from a previous test, partial spool reads, lock timing) were ruled out by the request log: every shim request reached its own test's server.

## Fix (21ef086, test-only)

- `apps/cli/test/shim/harness.ts`: requests whose user agent starts with `curl/` (the shim's only HTTP client) are recorded in `received`; any other request goes to a new `foreign` list and gets the same answer.
- `apps/cli/test/shim/claude-code-shim.test.ts`: the proxy test also asserts that no `foreign` request carries the token.

Theoretical risk left as is: `deadUrl()` releases a port before the shim connects; another process could take it in between. Never observed (all 150 logged shim posts reached the right server).
