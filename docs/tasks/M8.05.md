- **Live runs:** Codex CLI 0.166.0, `gpt-6-luna` at effort `low`, throwaway repo under `/tmp`, every setting a per-invocation `-c` override, OTLP/HTTP JSON, hooks and `notify` pointed at a local recorder. - **Side effect to know about:** in the first dry run the owner's roborev `Stop` hook from `~/.codex/hooks.json` ran once in the throwaway repo, because `--ignore-user-config` does not skip `hooks.json`. roborev recorded no session for it. Every later run disabled the user hooks per invocation, and all user plugins too for the TUI runs.
- **NOT RUN:** committing the fixture JSONL files (`exec-hooks.jsonl`, `exec-events.jsonl`, `tui-hooks.jsonl`, `tui-hold-hooks.jsonl`, `notify.jsonl`, `otel-logs.jsonl`, `otel-metrics.jsonl`, about 118 KB together). - **Measurements:** permission hold: with an 8 s `PermissionRequest` hook, the TUI showed "Running hook" and no prompt until the hook returned (pane captured every 2 s). Hook latency: 70 to 150 ms per sync `python3` handler. Async hooks: zero lost across all runs (async count equal to sync count per event).
- **Decisions needed:** none for this ticket. A follow-up adapter ticket will need an owner call on the Codex permission hold window, because the S-1 and #116 rule (90 s, focus-independent) does not fit Codex, where a pending hook hides the terminal prompt.

- **Lessons:**
  - Codex `-c` dotted paths split quoted keys at dots. Pass a table that has a path-like key as one inline TOML value (`-c 'hooks.state={"<path>"={enabled=false}}'`).
  - `codex exec --ignore-user-config` still loads `~/.codex/hooks.json`, and the TUI also loads plugin-bundled hooks. A spike that uses `--dangerously-bypass-hook-trust` must disable user hooks and plugins explicitly, and check the `codex.hooks.run` metric's `source` to prove it.
  - `codex exec` forces `approval_policy = never`; test permission flows in the TUI under tmux.
  - In zsh, a bare `> file` runs `cat` reading stdin and hangs a tool call; use `: > file`.
