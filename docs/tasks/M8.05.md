Hook latency: 70 to 150 ms per sync `python3` handler. Async hooks: zero lost across all runs in the recorder files (async count equal to sync count per event), though the `codex.hooks.run` metrics show `SessionEnd` and `SubagentStop` only as synchronous.
- **Decisions needed:** none for this ticket. A follow-up adapter ticket will need two owner calls: (1) the Codex permission hold window, because the S-1 and #116 rule (90 s, focus-independent) does not fit Codex, where a pending hook hides the terminal prompt; (2) how protocol v1 represents a tool call whose outcome is unknown (`tool_call.finished.phase` allows only `succeeded` or `failed`).
- **Review outcome:** one fix round (roborev 7513) · findings: high 3, medium 1, low 1. Fixed in the doc: (1) a `PostToolUse` now maps to an unknown outcome, not `succeeded`, with each possible exit-evidence source assessed (hook `tool_response`, OTel `tool_result`, `sandbox_outcome`, `exec --json`); (2) a terminal answer resolves a held permission only on one unambiguous match (session, turn, agent, tool name, input), otherwise it stays open; (3) subagents are shown by `agent_id`, with no order-based naming; (4) `SessionEnd` and `SubagentStop` are configured synchronously, spooling within the hook timeout; (5) the fixtures README describes the files as committed.
- **Lessons:**
  - Codex `-c` dotted paths split quoted keys at dots. Pass a table that has a path-like key as one inline TOML value (`-c 'hooks.state={"<path>"={enabled=false}}'`).
  - `codex exec --ignore-user-config` still loads `~/.codex/hooks.json`, and the TUI also loads plugin-bundled hooks. A spike that uses `--dangerously-bypass-hook-trust` must disable user hooks and plugins explicitly, and check the `codex.hooks.run` metric's `source` to prove it.
  - `codex exec` forces `approval_policy = never`; test permission flows in the TUI under tmux.
  - A draft mapping must not turn missing evidence into a positive claim ("succeeded", "approved", a name). Write "unknown" and say which source could settle it.
  - In zsh, a bare `> file` runs `cat` reading stdin and hangs a tool call; use `: > file`.
