- **Design notes:**
  - `mask.ts` calls the engine's `redactText` and `redactJson` by relative path (the way `data/domain.ts` does) instead of copying rules. `maskSpans(text)` is the text pass the tests pin; `inputMaskSpans(toolInput, text)` adds values the JSON redactor seals whole, mapped to the displayed pretty JSON by a layout walk that is trusted only when it reproduces the text exactly.
  - `useCardTarget` keeps the last target for the selected agent until the selection changes, so the "Sent, unconfirmed" and "answered in the terminal" states are not removed by the event that closes the request. `OverlayRoot` uses the same hook to decide the sidebar.
  - The exact input route is `GET /v1/requests/:requestId/input?projectId=` from M4.04 (in parallel); this ticket codes to the shape the coordinator pinned and `api.test.ts` pins.

- **Lessons:** A mask that only reads the displayed text misses structure: the JSON redactor seals whole values by property name, so a card that shows pretty JSON needs the structured pass too, and the red phase should pin one nested and one separated name/value case. When a helper is pinned as text in, spans out, say whether it must also take the structured input. A review probe has to include the shape the reviewer is likely to try next, not only the shapes already named.
