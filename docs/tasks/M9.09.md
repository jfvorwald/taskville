- **Lessons:** `DemoOptions.speed` stamps `occurredAt` as `startAtMs + floor(atMs / speed)`, so a live run at N times never stamps an event after the wall time it is posted at (speed 1 and the offline stream take the old path and are unchanged). Correction to the earlier claim that nothing measures time from `occurredAt`: the domain attention selector flags silent trouble after 10 minutes from `lastSeenAt`, and crew idle marks a teammate quiet after 5 minutes. Both read the wall clock against `occurredAt`. With ahead-of-time stamps those checks could never fire at speed above 1; now they can, which is intended. Also the web store clock (break delay and quip windows) reads event age, which is what the stamping fixes. `tool_call.finished` `durationMs` stays in scenario time at speed above 1 (low, accepted). The `breaks` script now emits `activity.started` "implementing" with each resumed `session.prompt_submitted` (resetting the agent's activity to idle when it ends its turn so the second cycle emits it again). Plaza residual, in two parts and still one reservation source (`plazaClaim`/`heldByOther`): in `retarget`'s hold branch, an agent with no free safe point that is walking to its workstation and whose next waypoint is a plaza node held by another agent carries on to the workstation; and in `plan`'s stay branch, an agent told to stay while standing exactly on a plaza node another agent holds (the node it just left was handed to someone else, for any goal kind: slot, home or spot) no longer stops there but carries on along its path to the first point nobody holds, or to the end of the path. The general rule: an agent told to stay never stops on a node another agent holds. The seeded fuzz in `navigator.break.test.ts` found what the hand-written cases missed (the same plaza sharing recurred five times across M9.08 and M9.09), so keep it in the suite.
