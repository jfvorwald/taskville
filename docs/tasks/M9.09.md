The spec's clock model (6x with a 511 s backdate, written for ahead-of-time stamping) no longer holds, so its needs-you step needs a test-writer change: with `startAtMs + atMs / speed` every event is posted at an age equal to the backdate (511 s), so Brook's needs-you bubble window has always passed. A backdate of 120 to 130 s starts breaks at once but still leaves the bubble stale, so the spec needs a different way to age only the turn_ended records (for example a second producer run, or backdating by event) or to drop the backdate and wait for the 60 to 120 s break delay.

- **Lessons:** `DemoOptions.speed` stamps `occurredAt` as `startAtMs + floor(atMs / speed)`, so a live run at N times never stamps an event after the wall time it is posted at (speed 1 and the offline stream take the old path and are unchanged).
