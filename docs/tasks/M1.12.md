## Per-event order

1. `parseInputEvent` (schema version, type, envelope, payload).
2. Reject a string or key that is not well-formed UTF-16 (a lone surrogate), per event, since canonical JSON refuses it.
3. `producerPolicyViolation` (engine-only type, reserved `taskville:` source, demo provenance). Same order as the M1.17 reference model.
4. `unknown_project` if the project is not in the `projects` table. Nothing is created.
5. Normalize the payload: strip control characters, then `redactJson`, skipping per type the top-level fields whose schema type is an ID, enum, or timestamp (`UNMASKED_FIELDS` in `normalize.ts`). Nested values are always masked.
6. `clientContentHash` of the parsed event with the masked, untruncated payload.
7. Same source key: same hash is `duplicate` with the original sequence and event ID; different hash is `conflict`. This also works within one batch, because earlier events are already inserted in the open transaction.
8. Build the stored envelope: `reason` cut to 280 code points as `{ text, masked, truncated }`; `inputPreview` (2,000 code points) and `sourceValue` (200 UTF-16 units, the unit its schema counts) cut again after masking, since a marker can be longer than the secret; `eventId`, `receivedAt`, `ingestSequence = head + 1`. It must parse as a protocol stored envelope, or the event is rejected (`invalid_payload` with the path), for example a title that was only control characters.
9. Append, apply the reducer. After the loop, write the projection of every project that accepted an event; COMMIT; then `onCommit`.

A thrown error anywhere (the reducer, the database) rolls the whole batch back and surfaces as 500. A broadcast hook error is logged and the 200 still goes out, because the batch is committed.

## Choices worth a look

- **Control characters:** C0, DEL, and C1 are removed, except tab and line feed, so multi-line previews and summaries keep their shape. Carriage returns are removed. events.md says only "control characters stripped".
- **`heads`** in the response lists every project an event reached past the project check (accepted, duplicate, or conflict), with its head after commit. A batch that only hit unknown projects gets `{}`. The broadcast `CommittedBatch.heads` lists only projects that accepted an event.
- **Projection loading:** the stored projection is used when its reducer version and head match the project; otherwise ingest replays the project's log inside the transaction first. So the Unsorted project (no projection until the boot rebuild) and a stale projection both repair themselves.
- **Concurrency:** within one engine, requests are serialized because `ingest` is synchronous. Across connections (two engines on one file), `BEGIN IMMEDIATE` plus the busy timeout serializes them; the worker-thread test runs three writers with 500 events each on separate connections and checks a gap-free 2..1501 and a projection equal to a replay.

## Lessons

- Canonical JSON refuses lone surrogates, which JSON parsing and Zod string schemas accept, so any hash over producer text needs a per-event well-formedness check first, or one bad string fails the whole batch.

- A credential-less POST without `Origin` gets 403 `forbidden_origin` before the credential check can return 401, so a test for "no credential" must send an allowed `Origin`.
- A `node:worker_threads` worker can load a `.ts` file under Vitest, and workspace packages resolve through their symlinks to real paths outside `node_modules`, so Node's type stripping applies. That makes real multi-connection SQLite concurrency tests cheap.
- Masking can make a string longer (a 6-character secret becomes a 20-plus character marker), so any field with a maximum length needs a cut after masking, or valid input turns into an invalid stored envelope.
