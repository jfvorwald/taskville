- **Known limits:**
  - Evidence bodies are still fetched from the engine under privacy. Privacy is display-only, so a browser extension, the network panel or a heap dump can still see them.
  - If the editor template ever becomes configurable, it must come only from engine config, never from agent or evidence data. Today `LiveTab` takes `editorTemplate` only from its caller and `ConnectedLiveTab` passes none, so the default `vscode://file{path}` applies.
  - Live Write cards still show the content inline when privacy is off (existing tests pin it), and the expanded `ExpandableCode` shows it again, highlighted, with the editor link.
  - Secrets split by zero-width characters (security L3): `CodeBody` now masks them, by re-running redaction with invisible characters stripped and using that result when it finds more secrets. The Live tab's `safe()` and the Files tab still redact the raw text only, so the gap remains there.
- **Review outcome:** not yet confirmed (see PR line).
- **Lessons:** `pnpm --filter @taskville/web test` only includes `test/**/*.test.ts`, so tests under Owns paths run only through the browser config. React Aria `Switch` hides its input under its label, so a test that clicks the `switch` role cannot reach it; a native checkbox with `role="switch"` can be clicked. Biome wants `aria-checked` on it. Shiki exports `bundledThemes` and `bundledLanguages` from `shiki/themes` and `shiki/langs`; those are lazy per item. The agent-guard hook blocks shell writes (heredoc, sed -i) into directories that hold test files; use Write or Edit. A privacy rule written as a deny-list of tools leaks everything it did not name; make it one early return. Evidence parsing masks a path before a link check sees it, so a link check must also reject the `[REDACTED` marker.
