## Red

Test file: `apps/engine/test/feed/feed-parallel.test.ts` (10 tests: 5 scenarios, each for a turn end `session.turn_ended` and a session end `session.ended`; one agent with two running calls `toolu_par_a`, `toolu_par_b` in one session).

Decided frame scheme (for the implementer): one boundary event may produce several `toolcall` frames, one per call the reducer closed as `unfinished`. Only the last frame of an event carries `id: <ingestSequence>`; earlier frames of the same event carry no `id`. A client that reconnects mid-event with `?after=<previous id>` receives the whole event's frames again (full ToolCall snapshots keyed by `toolCallId`, so replay is idempotent). The id type does not change. The feed reuses the reducer's boundary-closure rule, exported (export only) from `packages/domain/src/reducer/entities/tool-calls.ts`, instead of duplicating it. `ToolCallTracker.apply` currently returns one call; it needs to return all closed calls, and `FeedSubscriber` (`PendingFrame`, `writeFrame`) must write `id` only on the last frame of an event. Also update the feed section of `specs/001-headless-foundation/contracts/http-api.md`.

## Red round 3

From roborev re-review 6775 and post-commit 6772 (one valid medium). `ToolCallTracker` looks up boundary closures in the retained post-event state. Retention runs in the same reduce: a finished session owner is kept only by its late running call, so the boundary that closes that call lets retention drop the owner and its session (when 50 newer agents have finished). The unregistered helper's running call in that session is closed by the same boundary, but the feed no longer sees the owner as session owner and leaves it `running`.

Tests (in `apps/engine/test/feed/feed-parallel.test.ts`, describe "a helper's call closed by a boundary whose owner retention then drops"): the owner starts a session, finishes, starts a late call; 50 newer agents finish; an unregistered helper starts a call in the session; the owner's `session.turn_ended` closes both. The helper's feed must show `running` then `unfinished` (backlog) and the `unfinished` frame live, with the boundary's id.

Fails now: backlog `expected [ [ 'toolu_ret_helper', 'running' ] ] to deeply equal [ ...2 ]`; live `expected [] to deeply equal [ Array(1) ]`. Control: with 10 newer agents instead of 50 the same tests pass, so retention is the cause (the constant is `RETAIN_FINISHED_AGENTS` = 50).

Command (from `apps/engine`): `pnpm exec vitest run test/feed/feed-parallel.test.ts -t "retention then drops"`. `pnpm run typecheck` and biome: clean.

Note for the implementer: the closure lookup needs the sessions and agents as they stood after the event's slices but before the retention step (or an equivalent that does not depend on retained records).
