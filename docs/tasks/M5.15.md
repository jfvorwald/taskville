## Red

Test file: `apps/engine/test/feed/feed-parallel.test.ts` (10 tests: 5 scenarios, each for a turn end `session.turn_ended` and a session end `session.ended`; one agent with two running calls `toolu_par_a`, `toolu_par_b` in one session).

Decided frame scheme (for the implementer): one boundary event may produce several `toolcall` frames, one per call the reducer closed as `unfinished`. Only the last frame of an event carries `id: <ingestSequence>`; earlier frames of the same event carry no `id`. A client that reconnects mid-event with `?after=<previous id>` receives the whole event's frames again (full ToolCall snapshots keyed by `toolCallId`, so replay is idempotent). The id type does not change. The feed reuses the reducer's boundary-closure rule, exported (export only) from `packages/domain/src/reducer/entities/tool-calls.ts`, instead of duplicating it. `ToolCallTracker.apply` currently returns one call; it needs to return all closed calls, and `FeedSubscriber` (`PendingFrame`, `writeFrame`) must write `id` only on the last frame of an event. Also update the feed section of `specs/001-headless-foundation/contracts/http-api.md`.
