## Code-review fixes

- **Rebuild on tab return.** `RenderPacer`'s `onResume` calls `presentationEpoch.bump(hiddenForMs)` (`city/runtime/epoch.ts`). `CityAgents` subscribes to the epoch and calls `rebuildPresentation(nav, now, reducedMotion, hiddenForMs)` (`city/runtime/rebuild.ts`), so walkers snap to where their paths end after a long absence (ARCHITECTURE.md 2.8).
- **Motion signals.** The throttle's signals come from `motionSignals(labels, cameraChanged, touched)` (`city/runtime/motion-signals.ts`) instead of inline logic in `RenderPacer`.
- **Working agents draw at 20 fps by design (CTO decision).** Only walking, arriving and departing count as agents moving; a working agent's loop does not hold the pacer at 60 fps, which keeps the idle throttle effective. A comment at the signal in `RenderPacer` says so.
- **Selected row is `aria-selected` (CTO decision).** React Aria's `GridListItem` filters out `aria-current`, so the earlier `data-current` and `aria-current` attributes never reached the DOM as an accessible state. `AgentList` now uses `GridList` with `selectionMode="single"`, `selectionBehavior="replace"` and `selectedKeys` bound to `selection.selectedId` (empty when null). Enter or click still calls `selection.select(id)` (via `onAction` and a non-empty `onSelectionChange`), so the M3.11 selection (`camera-controls[data-selected-id]`) behaves as before; clearing the set by clicking the selected row again is ignored. The dead `data-current` and `aria-current` attributes are removed and the marker style is now `.row[data-selected]`. No animation or transition was added, so reduced motion holds (the accessibility e2e covers it).

## Lessons

- A component library can silently drop an ARIA attribute you pass to it; assert the attribute on the rendered DOM, and prefer the library's own state (selection) over a custom attribute.
