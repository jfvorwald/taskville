## What landed

`apps/web/src/overlays/host/` and `apps/web/src/overlays/header/`, plus a two-line mount.

### Registry (`host/registry.ts`, `host/types.ts`)

```ts
const registry = createOverlayRegistry([countsHeaderOverlay]);   // add yours in overlays/index.tsx
registry.register({ id, slot, modes, Component }); // returns a disposer; throws on duplicate id, unknown slot, empty modes
resolveActiveOverlays(definitions, { mode, enabled, sidebar }); // pure: Record<slot, definitions[]>
```

- Slots: `header`, `sidebar`, `timeline`, `world-labels`, `bubbles`. Stacking back to front: world-labels, bubbles, timeline, sidebar, header.
- Exclusive slots (`EXCLUSIVE_SLOTS`): only `sidebar`. It keeps the chosen sidebar if enabled and in mode, else the first that qualifies. The other slots take any number of overlays, in registration order.
- An overlay renders only if it is registered, enabled (`enabled` ids, owned by whatever drives presets) and supports the current mode.
- Each overlay sits in an error boundary; one crashing logs and renders nothing, it does not take the app down.

### OverlayProps (what every overlay receives)

`mode`, `selectors` (read-only, `Selector<T>` = `{subscribe, getSnapshot}` for `useSyncExternalStore`; today `counts`), `selection` (`selectedId`, `select`), `anchors`, `intents` (`available`, `run`; `run` is a no-op in history mode), `settings` (`get(key, fallback)`, `set(key, value)`, JSON, namespaced `taskville.overlay.<id>.<key>`, tolerant of broken storage).

### Pointer routing

The host, every slot and every anchored item are `pointer-events: none`. An overlay wraps what should take the pointer in `<InteractiveRegion>` (or passes `interactive` to `<Anchored>`). A browser test clicks a button under the host through its empty space and another through an interactive region.

### World-labels slot and anchors (the interface M3.05 / M3.15 use)

- **City side:** `worldAnchors` (from `overlays/host/index.ts`, also `createAnchorSource()` for tests) is the shared store. Publish with `worldAnchors.setAnchor("agent:<id>", [x, y, z])`, `removeAnchor(id)`, or `replaceAnchors("agent:", { ... })` (one notification). Setting an unchanged position is free, so calling it every frame is fine.
- **Camera side:** `<AnchorBridge source={worldAnchors} />` inside the `<Canvas>` publishes view-projection and canvas size each frame. Already mounted in `SceneRoot.tsx`.
- **DOM side (a world-labels or bubbles overlay):**

```tsx
function AgentLabels({ anchors, selectors }: OverlayProps) {
  return (
    <AnchorLayer source={anchors} gap={4} margin={48}>
      {agents.map((a) => (
        <Anchored key={a.id} id={a.id} anchorId={`agent:${a.id}`} priority={a.needsYou ? 9 : 0}>
          <Label agent={a} />
        </Anchored>
      ))}
    </AnchorLayer>
  );
}
```

  Labels sit centred above the projected point. Collision: best `priority` first (ties by id, so no flicker), a colliding box is lifted until clear and hidden if that leaves the top of the layer; boxes behind the camera, past the planes or beyond `margin` px off screen are hidden and take no space. Positioning is a CSS transform (no layout reflow). Use one `AnchorLayer` per overlay; bubbles and labels in different overlays are laid out independently, so give bubbles a higher stacking slot (they are) and keep them off labels with priority if they must not touch.
- Pure pieces, unit tested in node: `projectToViewport` (column-major `Matrix4.elements`, +y down, w <= 0 and out-of-range depth are invisible), `layoutAnchored`.

### Header counts (`header/`)

`countsHeaderOverlay` (`id: "counts-header"`, slot `header`, both modes). Reads `selectors.counts`: `{ active, needsYou }`, renders `3 active · 1 needs you` (`need you` for any count but 1) in a `role="status"` with a spelled-out label.

## Lessons

- Unit tests here run in node (`test/**/*.test.ts`), so putting projection, collision and registry logic in pure `.ts` modules made the geometry testable without a browser; the React layer stays thin and gets browser tests.
- `document.elementFromPoint` assertions need element identity, not `textContent`: a wrapper that contains the text matches it.
- Biome's `noComponentHookFactories` flags fixture components built inside helper functions in tests; a targeted `biome-ignore` with a reason is the fix.
- Under parallel workers, the root `pnpm check` hit 5 s timeouts in two `@taskville/cli` tests that pass alone; a loaded machine makes the cli integration tests flaky.
