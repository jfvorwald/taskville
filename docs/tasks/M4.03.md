    - High, a `permission.decide` left `requested` by an engine stop is recorded `failed` although the agent may have the answer: accepted as honest reasons. Start-up recovery still records `failed` (the protocol has no indeterminate status) but the reason now says the outcome is unknown: "The engine stopped before the outcome was recorded; the decision may have reached Claude Code" (and "...the session may have opened" for `session.open`, also used on a repeated POST).

    - Medium, a `permission.decide` can close the request while `session.open` awaits `realpath`: rebutted and accepted by the CTO. The command was accepted while the request was open; the race is just command ordering, and opening a terminal for an answered request is harmless.

    - Medium, replaying a session.open that failed with `request_not_open` or `request_session_mismatch` returns 502 `opener_failed`: not changed. Existing behavior from earlier rounds, outside this round; persisting the code and status needs a protocol decision and a follow-up ticket.

- **Authorized exceptions used:** `apps/engine/src/http/app.ts` (the `/v1/commands` stub passes requests on once `registerCommandRoutes` marks the app, and still answers 501 when no service is registered), `specs/001-headless-foundation/contracts/http-api.md` (the `/v1/commands` shapes and codes), and this report.
- **Known limitations:**
  - `permission.decide` replays by status: a later M4.04 move of a `delivered` command to `failed` or `expired` replays as `request_not_open` or `request_expired`.
  - A command whose `command.delivered` append failed reads `delivered` only in this process; after a restart it is ended `failed` at service start.
  - The opener check is a resolve-then-spawn sequence; a directory swapped between the check and the spawn is not caught.
  - The root check and the launchable-name check apply only when the opener template uses `{cwd}`; copy-only mode and templates without it never hand the directory to a process.
  - A `session.open` for a session with no recorded `workingDirectory` omits `cwd` from the result; a template that uses `{cwd}` then fails with the directory message.
  - `taskville serve` does not register the command routes yet; M4.04 (#61) wires the service and the bridge.
- **Lessons:** A test helper that reads a response body must not be called twice on one response; the red phase should run each new test once against a stub before it is handed to green. Pinning a result shape that the event payloads cannot carry needs a protocol change decided in the red phase, not found at review. A command that targets a request needs its open-state and ownership rules pinned in the first red round, not at the third review.
