## Choices to review

1. **`POST /v1/projects` lives in the engine** (forced extra path, `apps/engine/src/projects/`), with a new CLI-only `projects` scope (`auth/scopes.ts`) and `project_exists` in `http/errors.ts`. `createProject` writes the row, `project.created` at sequence 1, and the initial projection in one transaction. It refuses names or roots that redaction would mask, that contain control characters, or that are not well-formed Unicode, because this engine-authored event bypasses the ingest masking. IDs follow the config-file rule (`^[a-z0-9][a-z0-9-]{0,62}$`, default `slugify(name)`); names are 1 to 100 characters.
2. **Config-file projects** are registered at every start when their ID is absent (#110 default); the file is never edited, and an existing project with that ID is left as it is.
3. **Pairings are in memory** (`PairingStore` default records). Decision #113 is open, so `SqlitePairingRecords` is not wired; a restart means pairing the browser again.
4. **"Active" leaves out `unknown` activity.** cli.md says active means "neither idle nor waiting", but the reducer records `unknown` until an agent reports an activity, so the basic fixture's idle Reviewer would count, against the quickstart's `1 active`. Counting an unknown activity as active would present a guess as a fact (constitution IV), so `unknown` is excluded. cli.md's wording should gain "or unknown" (outside Owns).
5. **Usage errors exit 1** (cli.md does not name a code). A line that is not JSON is rejected locally as `invalid_envelope`, as in `fixtures/events`; an event that would not fit a request of its own (over 5 MiB) is rejected locally as `event_too_large`; larger-than-budget events that fit are posted alone.
6. **Line format** of the tree: `name (kind) · connection · activity[ (heuristic)] · task title · finished · attention`, with `(kind)` omitted for sessions and the attention as cli.md gives it (`needs you: <kind> <tool> - <reason>`, `trouble (heuristic): quiet for N min`, `[masked]` and `[truncated]` markers).

## Lessons

- CI checks the PR merged into the current main, so a green local `pnpm check` on the branch is not enough once main moves; merge main and check `mergeStateStatus` before trusting a push.

- The contract's "active" rule and the quickstart's expected header disagreed once a real reducer was in the loop: the reducer marks a fresh session's activity `unknown`. End-to-end goldens against the quickstart caught it; unit tests of the renderer would not have.
- Events the engine writes itself (`project.created`) skip the ingest pipeline, so they skip its masking too. Any engine-authored event built from user input needs its own check.
- Running `serve` in process with an injected engine clock made the end-to-end test deterministic (no heuristic "quiet for N min" from wall time) without adding a test-only CLI flag.
