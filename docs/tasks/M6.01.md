- **Lessons:** `receivedAt` is not guaranteed sorted if the engine clock steps back, so timestamp positions are resolved by a scan, not a binary search. A cursor that must keep a page walk stable has to carry the resolved upper bound always, because both an explicit `to` past the head and an omitted `to` resolve to a moving head; a bound read back from a cursor is clamped to the head. `Date.parse` accepts hour 24 and drops digits past milliseconds, so the grammar check and the lower bound must handle both. `Date.UTC` reads years 0 to 99 as 1900 to 1999; use `setUTCFullYear`. A route-table allowlist test elsewhere in the repo breaks whenever a route is added; the ticket that adds routes should name that test in its Owns.

## Implementation notes

- Routes live in `apps/engine/src/timelines/` and are registered by `bootEngine` (`apps/engine/src/stream/boot.ts`, one line plus import). The contract is in `specs/001-headless-foundation/contracts/http-api.md` ("Timelines").
- State is a replay of events 1 to `at` over the existing reducer. At the head, a current stored projection (same reducer version, same head) is reused. Attention is evaluated at the `receivedAt` of event `at`.
- Nothing under `src/timelines` writes, imports the command module, or touches ingest.
