## What storage exports (`apps/engine/src/storage/index.ts`)

| Name | Use |
| --- | --- |
| `openStorage(path, { now?, busyTimeoutMs? })` | Owner-only files, WAL, `synchronous=NORMAL`, foreign keys, defensive mode, migrations. Refuses a symlink, a non-regular file, or a schema newer than the code |
| `Storage` reads | `project`, `projects`, `head`, `projection`, `findEventBySourceKey` (returns `contentHash` and the stored envelope for duplicate acks), `events(projectId, after?)` in sequence order, `journalMode` (for `/health` `walMode`), `schemaVersion` |
| `storage.transaction(tx => ...)` | `BEGIN IMMEDIATE` / `COMMIT`, `ROLLBACK` on any throw. Synchronous callbacks only, no nesting, the `tx` handle is dead after the call. `tx.insertProject`, `tx.appendEvent(envelope, contentHash)`, `tx.writeProjection({ projectId, reducerVersion, head, state })` (returns the `stateHash` it stored) |
| `rebuildProjection`, `rebuildStaleProjections(storage, reducer)` | Boot step; reducer is a parameter (`{ version, initial(projectId), apply(state, event) }`), so the domain reducer (#9) plugs in without storage changes. Stale means missing, other reducer version, or head behind the project |
| `ensureUnsortedProject(storage)` | Creates `unsorted` (builtin) with its `project.created` event at sequence 1, once |
| `clientContentHash(fields)` | R-6 hash of an event's client-supplied fields (engine-assigned ones dropped) |
| `storage.pairingRecords()` / `SqlitePairingRecords` | `PairingRecords` over the `pairings` table (digests only) |

## Integrity enforced in the schema, for every connection

- `events_no_update`, `events_no_delete`: abort any UPDATE or DELETE on `events`.
- `events_insert_checks` (one trigger, ordered checks): aborts an insert that collides with an existing event ID, sequence, or source key, which also stops `INSERT OR REPLACE` (REPLACE deletes without firing DELETE triggers unless `recursive_triggers` is on); then requires `ingest_sequence = projects.head + 1`.
- `events_advance_head`: the insert advances `projects.head`; `projects_head_matches_log` refuses any other head value. So the head is always the last sequence and the log is gap-free per project.
- `projects_builtin_no_delete`: Unsorted cannot be removed.
- `writeProjection` refuses a head that is not the project head, so a projection never claims events it does not cover.

## For the ingest (#13) and serve (#16) teammates

- Ingest flow per batch: `storage.transaction(tx => { findEventBySourceKey -> duplicate/conflict; else appendEvent(envelope with ingestSequence = tx.head(p) + 1, contentHash); apply reducer; writeProjection(...) })`, then broadcast after it returns. A thrown error rolls the whole batch back, including the head.
- `clientContentHash` hashes whatever object it is given; ingest must pass the masked, untruncated fields (R-6 and R-13), not the stored envelope.

## Lessons

- Node 26.8.2 `node:sqlite` does not export `Database` or `Statement`, although ARCHITECTURE.md, research.md, plan.md, and data-model.md all say to use them; only `DatabaseSync` and `StatementSync` exist. Check a "use the new names" claim against `Object.keys(require("node:sqlite"))` on the pinned Node. Decision #133.
- SQLite does not document the firing order of separate triggers on the same event, and here a later-created BEFORE INSERT trigger fired first, so the expected error message did not appear. Put ordered checks in one trigger body as `SELECT RAISE(...) WHERE ...` statements.
- `INSERT OR REPLACE` deletes the conflicting row without firing DELETE triggers (unless `PRAGMA recursive_triggers` is on), so a DELETE trigger alone does not make a table insert-only.
- SQLite creates the `-wal` and `-shm` files with the database file's permission bits, so creating the database file 0600 first keeps all three owner-only; existing loose files still need a chmod.
