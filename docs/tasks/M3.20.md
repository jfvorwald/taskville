- **Lessons:** `DayNightLighting` is a sibling of `ThemedCity`, so it cannot reach the materials `useCityMaterials` creates inside `CityScene`. The shared level is a small module store in `materials.ts` (`setSharedEmissiveLevel`): lighting publishes it, `useCityMaterials` reads it with `useSyncExternalStore` and applies it in a layout effect, so materials recreated on a palette change are scaled before their first paint. Nothing runs per frame and nothing allocates; `nightness` is already smooth, so there is no separate animated ramp and nothing for reduced motion to gate. `materials.ts` must not import from `lighting/` (themes imports buildings, so that would be a cycle); the dependency points lighting to buildings.

## Design notes

- `emissiveLevel(nightness)` is `0.15 + 0.85 * nightness`, clamped, exactly 1 at night.
- `applyEmissiveLevel` sets `color.set(paletteHex).multiplyScalar(level)`: always from the palette, so no drift, and level 1 is the palette hex.
- The store defaults to level 1, so a city mounted without `DayNightLighting` keeps the palette glow.
- **Mode switch at nightness 0.5:** the level is continuous (0.575), but the theme palette flips day to night there, so the glow hex steps. Cyberpunk: window `#ffe0a0` to `#fff2c8` (a few percent brighter), lamp `#5fe3ff` to `#9af5ff` (red channel 0x5f to 0x9a, a visible but small step on lamp heads). Other themes step similarly (steampunk, solarpunk, aero change a few percent). Not fixed here: smoothing it means blending day and night palettes by nightness, which is a lighting and theme design change outside this ticket.
