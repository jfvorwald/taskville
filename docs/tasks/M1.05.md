## Contract choices (for the reviewer and the domain, storage, and fixtures teammates)

1. **Agent kind gains `unknown`.** data-model.md lists `session`, `subagent`, `lead`, `teammate` but also says any source value not in an enum is stored as `unknown` with `sourceValue`, and ARCHITECTURE.md section 6 says "Anything unrecognized is kept as `unknown`". The architecture wins, so `AGENT_KINDS` ends in `unknown`. An `unknown` kind skips the `parentAgentId` and `teamId` rules, since Taskville cannot know them. data-model.md's enum list should get `unknown` too (outside this ticket's Owns).
2. **Open vs closed enums.** Open (unknown with `sourceValue`): agent kind, task status, activity. Closed (unrecognized value rejected as `invalid_payload`): `tool_call.finished` phase, request kind, resolution, command type, provenance, because they drive requests, commands, and attention, whose enums data-model.md gives no `unknown` member. `sourceValue` sits beside the enum field in the payload, is kept only when the value is `unknown`, and is dropped when a known value arrives with one, so parsing twice gives the same result. Matching is case-sensitive.
3. **Required envelope IDs per type.** "As relevant to the type" is made concrete: `agent.*`, `activity.*`, `tool_call.*`, and `request.opened` need `agentId`; `session.*` need `agentId` and `sessionId`; `task.*` need `taskId`. Missing ones are `invalid_envelope` with the field as `path`, so the reducer never guesses the subject. The exported JSON Schema lists them in each member's `required`.
4. **Strict objects.** Unknown fields are rejected (`invalid_envelope` at the top level, `invalid_payload` inside `payload`) rather than silently stripped. Engine-assigned fields (`eventId`, ...) on input are therefore rejected.
5. **Characters are Unicode code points** for the 280, 4,000, and 2,000 limits, so a limit never splits a surrogate pair. The redaction module (M1.20, #24) must truncate by code points to produce a `text` this schema accepts. An input `inputPreview` over 2,000 is rejected, like an input `reason` over 4,000.
6. **Input vs stored payloads.** `reason` is a string on input and `{ text, masked, truncated }` when stored; the masking and truncation step between them is M1.20's, not the protocol's.
7. **Error codes beyond http-api.md:** `invalid_request` (400), `payload_too_large` (413), `not_found` (404), `internal_error` (500), because the contract names those statuses without codes.
8. **Snapshot `state` is an opaque record**, so `protocol` does not depend on `domain`; the domain can narrow it with `snapshotResponseSchema.extend({ state: ... })`.
9. **Rejected results** omit `sourceEventId` when the event had no valid one (`rejectedResult` handles this).
10. **Git:** `sha` is 7 to 64 lowercase hex characters; `git.commit` parents may be empty (root commit); `git.merge` needs at least 2 parents.
11. **SSE frames** are described after the `data` line is JSON-parsed and `id` read as a number; an `event` frame's `id` must equal `data.ingestSequence`.
12. **`late` is accepted from producers**, as events.md lists it as an optional input field.

## Risks and follow-ups for the lead

- Engine ingest (#7, #11): decide whether the batch route forces `late: false`; as written, a producer may set `late: true` on its own events (it can only suppress its own needs-you, never create one).
- Domain (#9, #10): handle agent `kind: "unknown"` and read `sourceValue`; the closed enums never need an unknown branch.
- Fixtures (#12): `invalid.jsonl` lines can use `parseInputEvent` to assert codes; every rejection carries a dotted `path`.
- Spike S-2 (M1.04): a subagent's parent can become known only after it registers, which fits `agent.registered` as an update. But S-2 also asks for a provisional parent link and split-pane permission attribution labelled as heuristic, and v1 payloads have no heuristic flag on `agent.registered` or `request.opened`. If the owner's G1 decision keeps those heuristics, M2 needs a protocol addition (for example `parentHeuristic: boolean`); nothing was added speculatively here.
- Zod 4.6.7 silently drops a `__proto__` key in `z.record` values (for example `command.requested` `payload`) rather than adopting it as a prototype; a test pins that.

## Lessons

- An object-level transform is the only way to keep a raw enum value as a sibling `sourceValue`; a field-level transform loses it. Splitting payloads into input and stored maps kept the stored schemas transform-free, which is also what lets `z.toJSONSchema` export them with `io: "output"`.
- Zod refinements do not reach JSON Schema, so per-type requirements enforced by `superRefine` have to be added to the exported documents by hand, or adapter authors see them as optional.
