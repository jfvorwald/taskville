## What landed

`apps/web/src/overlays/settings/`, plus a three-line mount in `overlays/index.tsx`.

- **`store.ts`**: `createSettingsStore(storage)` returns a `SettingsStore`, a `Selector<SettingsValues>` plus `set(key, value)`. `getSettingsStore()` is the app-wide instance over `localStorage` (lazy; in memory only if storage is blocked).
- **`SettingsValues`**: `{ theme: string; dayNight: "auto" | "day" | "night"; reducedMotion: "system" | "on" | "off" }`. Defaults: `cyberpunk`, `auto`, `system`. Invalid stored values fall back to the default; invalid `set` calls are ignored.
- **`resolveReducedMotion(setting, systemPrefers)`**: pure helper for consumers.
- **`SettingsPanel.tsx`**: sidebar overlay `settings-panel`, both modes. A "Settings" disclosure button (collapsed by default, `aria-expanded`) opens React Aria radio groups for theme, day and night, reduced motion, and two disabled "Coming later" switches (sound, hide code in the city). Keyboard: tab to a group, arrow keys change the choice.
- **Storage keys** are `taskville.overlay.settings-panel.<key>` (JSON), the same shape the host's namespaced `settings` API uses. The panel does not use `props.settings`: the theme and lighting systems must read the values when the panel is closed or not mounted, so the store owns them. Nothing goes to the engine.
- Sound and code privacy are not in `SettingsValues` yet; the switches are inert placeholders.

## Review fixes (green phase)

Red tests for the review findings were committed first (1db8c30). Source changes are in `store.ts` and `SettingsPanel.tsx` only.

- **Cross-tab (finding 1):** `createSettingsStore` listens for `storage` events when `window` and a storage exist (guarded for node). It ignores other keys and other storage areas, re-reads and validates the changed key (a null key re-reads all), replaces the snapshot and notifies only when a value changed. There is no dispose path on the store, so the listener lives as long as the store. `set` now writes whenever the stored value differs from the new one, even if memory already matches.
- **Unknown theme (finding 2):** the panel's theme RadioGroup value is `DEFAULT_SETTINGS.theme` when the stored theme is not in `themes`, so Cyberpunk shows checked.
- **Theme id (finding 4):** the theme validator accepts only `/^[a-z0-9][a-z0-9_-]{0,63}$/`. Invalid stored values fall back to the default; an invalid `set` is ignored.
- **Placeholder names (finding 5):** the disabled switches keep `aria-label` (the name) and gain `aria-describedby` pointing at the visible "Coming later" note.

## Lessons

- React Aria Components render radio and switch inputs visually clipped inside their `<label>`: component tests click the label text (`getByText(..., {exact: true})`), then assert on the role.
- Do not give a RAC group both `aria-label` and a `<Label>` child: the name comes out doubled ("Day and night Day and night") and `getByRole` by name misses it.
- Text and a note span inside one Switch label run together in the accessible name; use `aria-label` for the name and `aria-describedby` on the note so the note is still announced.
