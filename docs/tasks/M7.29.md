- **Lessons:** `checkInstalledLock` now takes the platform (default: process.platform, process.arch, glibc or musl on linux). An omission is allowed only when the committed os/cpu/libc lists exclude that platform, with `!negation` entries understood. Committed package and snapshot keys missing from the installed lockfile are refused under the same allowance. Two scanner gaps surfaced: inline snapshot entries (`name@1.0.0: {}`) were not read as keys, and the committed lockfile starts with a separate package-manager document that node_modules never contains, so only the last document is compared.
