Interfaces the tests assume (the implementer may not choose differently without updating the tests):
- `stateAtSequence(storage, project, upTo, { logger })`: a pino-style logger; any level counts, exactly one call for one failing step.
- `rebuildStaleProjections(storage, reducer, { logger })`: same logger as a third argument.
- Batch size: at most 20 rows per `checkpoints().put` call, on the seek path and in the backfill.

Failing now, each for the intended reason (assertion, not import or typo):
- Seek path, non-busy error logged once without bodies and seek still right: SQLITE_FULL, SQLITE_READONLY, unknown error on put; error from prune; error from delete (5 tests). Fails: logger never called.
- Batching: cold seek with interval 50 writes 52 rows in one put (expected at most 20); boot backfill over a 50,005-event LIVELY log writes 100 rows in one put (2 tests).
- Backfill validation: wrong version, unparseable JSON, hash mismatch, state of another head, each at sequence 1000, are left in place by boot instead of replaced (4 tests).
- Boot: SQLITE_FULL and SQLITE_READONLY on put make `rebuildStaleProjections` throw instead of logging once and continuing (2 tests).

Pins that pass on main (7): busy (errcode 5, 6), message-only lock error and "wait budget spent" stay silent on the seek path (4); a complete healthy cache is not rewritten; a seek after a failed backfill still answers and fills the cache; a busy error at boot is not logged.

## Green

- `apps/engine/src/storage/checkpoints.ts`: `CHECKPOINT_BATCH = 20`, `putInBatches`, `UpkeepLogger`, and `trusted()` moved here (now takes the reducer version) so the seek path and the backfill share it.
