## Green round 2

- Log fields are an allowlist: `upkeepFields()` in `apps/engine/src/storage/checkpoints.ts` returns only a numeric `errcode`; the log message is a fixed string per call site. The raw SQLite message is never logged.
- `isBusy` returns false for a non-object, and `upkeepFields` tolerates one, so a thrown `null` or `undefined` is a non-busy error logged without a message and never fails a seek or boot.
- Memory: the cold seek (`timelines/checkpoints.ts`) and the boot backfill (`storage/rebuild.ts`) write each batch of at most `CHECKPOINT_BATCH` (20) rows as soon as it fills. The event cursor is exited first and re-opened from the last sequence, so no write happens under it and at most one batch is held. After a failed seek write no later batch is built or tried; the backfill stops. `putInBatches` was removed (unused).
- Results: `checkpoints-hardening.test.ts` 32 passed; `pnpm run typecheck` and biome clean; `pnpm --filter @taskville/engine test` 1003 passed, 5 timing failures under load average about 36-43 (feed/limits, checkpoints.test.ts, checkpoints-followups x3); those three files rerun alone once: 43 passed (flakes). `pnpm check` skipped per lead.
