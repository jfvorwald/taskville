- **Decisions needed:** none. Choices made inside the ticket:
  - A null `waitingSince` means not eligible. A null `waitingEventId` seeds with an empty string.
  - Placement is causal: segments are placed in order of start time (ties by agent ID) against placements still running at that start. A segment's site and spot are fixed at its start, so they only change at the seeded boundary, and the result does not depend on input order.
  - When the preferred place is full, the agent tries another plaza activity, then any site with room. When everything is full the agent stays off break for that segment and retries at the next. Break is never forced past the spot counts.
  - A waiting record 24 h old or more shows no break (same bound as quips), which caps the segment walk.
  - Conversations pair agents by place (not by activity), sorted by ID, two at a time. The turn counts from the later of the pair's current segment starts.
- **Review outcome:** roborev 7275, two medium findings.
  - Medium 2 (night was judged once for the whole plan): fixed test-first. Red commit 97d578d added three failing tests; `BreakPlanInput.night` is now `boolean | ((ms: number) => boolean)` and the activity option list for each segment is built from night evaluated at that segment's start time. A boolean applies at all times.
  - Medium 1 (a neighbor leaving can shift an agent one spot within a site): answered as a deliberate tradeoff. The planner is stateless, so replay must equal live; placing each segment against the placements running at its start is what guarantees that, and remembering earlier spots would need state that live and replay would not share.
- **Lessons:** Anything time-varying that feeds a seeded choice (such as night) must be evaluated at the segment's start time, not once per plan, or a segment's activity changes while it runs. A stateless planner trades spot stability for replay equals live.
