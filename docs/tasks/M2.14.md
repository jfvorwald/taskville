## What changed (`packages/adapters/src/redact/text.ts`)

- The GitHub classic and fine-grained, Anthropic, OpenAI, and Stripe lookbehinds no longer exclude `_`. A known prefix after `_` (`mcp__server__ghp_...`, `MY_TOKEN_sk-...`) is masked by its token rule, the prefix is kept, and the kind is exact. A prefix glued to a letter or digit is still not a token start, so `work_live_...` and `task_sk-list` stay unmasked.
- The OpenAI pattern's digit lookahead `(?=[A-Za-z0-9_-]*[0-9])` became an `accept` check on the match. With `_` allowed before `sk-`, the lookahead rescanned a digit-free run from every `_sk-` in it (quadratic). The greedy body already consumes the whole run, so the result is the same: a match contains a digit exactly when the lookahead would have found one.
- **Checked and left as is:**
  - **JWT** keeps `_` excluded. Its body has to reach a `.`, so a run of `_eyJ` with no dot would be rescanned from every start. Matching it linearly would need a new run-splitting matcher, which is the kind of bypass surface L-17 warns about.
  - **AWS** and **Slack** already allowed `_` before the prefix.
  - **Anthropic, OpenAI, Slack and JWT after `-`** are still not token starts (for example `a-sk-ant-...`). That is outside this ticket; see "For the lead".

## What the gap really was

On main, a random token after `_` was already masked, but by the high-entropy rule, over the whole word including the prefix. The token rule missed two cases:
- a low-entropy token body (like the `a1B2...` test token in M2.03);
- any token in a word longer than the 256 characters the high-entropy rule looks at.

Rows that pass on main ("still masks a random ... in full") guard the first behavior from regressing.

## For the lead

- A `-` before an Anthropic, OpenAI, Slack or JWT prefix still blocks the token rule. The high-entropy rule catches random bodies in words up to 256 characters, so the remaining gap is the same narrow one this ticket closed for `_`. A follow-up could allow `-` for the prefixes whose own text starts with a letter (Anthropic, OpenAI, Slack). It would need the same timing rows, because their bodies include `-`.

## Lessons

- Check what an unmasked case really is before fixing it. The reported gap was narrower than it looked, because the high-entropy rule already caught random tokens. The failing rows had to use low-entropy bodies and words over 256 characters to show the real gap.
- Widening a lookbehind can turn a lookahead quadratic. The lookbehind was what kept the OpenAI digit lookahead linear, and the timing rows caught it at once (6 s). Check after the match (`accept`) rather than ahead of it when the body is greedy over the same class.
