Baseline (main pacer, same session, load 4.6): moving 60.0 fps, idle 20.1 fps, idle CPU 18.0%. First implementation (load 4.3): idle 18.9 fps, idle CPU 17.1%. Final (load 18.4, right after `pnpm check`): moving 60.0 fps, idle 20.0 fps, idle CPU 17.7%. The idle CPU on current main (about 18%) is about double the W1.01 profile (6.8 to 8.7%), so a larger cost appeared after the profile; it is being root-caused under #268 before W1.06's re-measure decision.
- **Decisions needed:** none (the #550 follow-up decision waits on the #268 root cause).
- **Review outcome:** see PR
- **Design:** idle, the pacer sleeps on a timer aimed from the frame timestamp at half a display frame before the next due idle frame; if a wake is not yet due it polls the next display frame instead of sleeping a full idle interval. Input events and the movement and camera stores wake it at once; camera position, zoom and the touched flag are polled at the idle wake.
- **Lessons:** a timer started when the callback runs drifts past the vsync it aims at; aim it from the rAF timestamp minus half a frame, and fall back to per-frame polling when a wake lands early, or idle quietly drops to 18.9 fps. Implementation and fix by the implementer; report by the lead.
