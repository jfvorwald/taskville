- **Decisions needed:** #560 (idle CPU budget after W1), defaults accepted: keep 20 fps idle, report quiet and pinned figures and instructions/s. Debugger root cause: the profile's lower CPU % came from a loaded machine running the same work on hot cores; retired instructions are flat.
- **Review outcome:** one fix round · findings: high 0, medium 1, low 1
- **Design:** idle, the pacer sleeps on a timer aimed at the frame pacer's carried deadline (`nextDeadline()`) minus its 2 ms tolerance and a 4 ms margin, so any refresh rate lands on the due vsync; if a wake is not yet due it polls the next display frame instead of sleeping a full idle interval. Input events and the movement and camera stores wake it at once; camera position, zoom and the touched flag are polled at the idle wake.
- **CI:** the first CI run failed the two idle tests (23 callbacks, 18.33 renders/s) while ~80 WebGL browser files shared SwiftShader. Debugger: the pacer is correct; the tests settled from `render()` while R3F mounted the pacer up to 1.5 s later, and the browser delivered frames with 67 to 850 ms gaps. Tests now settle from the pacer's first render and bound idle renders by delivered frames (floor(delivered / 3) - 2, which still fails the frame-skipping version at 46 of 58). The W1.02 idle control (at most 22 of 60 frames) read 23 once in a local all-city run and passed alone: flake, first on record.
- **Lessons:** a timer started when the callback runs drifts past the vsync it aims at; aim it from the rAF timestamp minus half a frame, and fall back to per-frame polling when a wake lands early, or idle quietly drops to 18.9 fps. Implementation and fix by the implementer; report by the lead.
