## What changed

- `apps/cli/src/commands/import.ts`: `importCommand(io, args)`. The kind (`git` or `transcripts`) is checked before the engine is contacted. Project and root default from the deepest configured root that contains the current directory (`GET /v1/projects`); `--project` and `--root` override. It then runs `POST /v1/imports` and polls `GET /v1/imports/:id` every `io.importPollMs` (default 500 ms) until a terminal status. It prints progress lines and a final summary (counts, malformed by code, truncated notice), or only the final record with `--json`. Exit is 0 on done and 1 otherwise. Engine codes `root_not_configured`, `import_running`, `unknown_import_kind` and `engine_closing` (matched by raw string) get plain messages. Output is counts and codes only, never source text.
- `apps/cli/src/main.ts`: `import` in the COMMANDS table and in USAGE.

## Review-fix round

- Containment rejects only `..` or a `..<sep>` prefix, so a child directory named `..work` is inside its root.
- The abort listener is removed when each poll timer completes, so none accumulate on `io.signal`.
- Ctrl-C during polling exits 1 with no stack trace, says the import keeps running on the engine, and prints its id.
- Status reads that fail with a dropped connection or a 5xx are retried (5 consecutive failures) before giving up with a message naming the id, that the import was started, and that the status could not be read. A 404 on the id says the import was not found (exit 2).
- Equal-realpath roots in different projects exit 1 and ask for `--project`, naming the projects.
- `--project X` alone, from outside its roots, uses X's only root; with several roots it asks for `--root`.
- Refusal codes are looked up in a `Map`, so `constructor`, `__proto__` and similar fall back to the engine's message.
- An unknown terminal status prints `import ended with status <s>` and exits 1.

## Last round

- An abort during `POST /v1/imports` exits 1 with no stack trace, says the import may already be running on the engine, and hints how to check (running `taskville import` again shows `import_running`, or `taskville status`).
