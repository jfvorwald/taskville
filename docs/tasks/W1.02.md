- **Root cause:** the pacer requested its next animation frame before calling `invalidate()`, so R3F's demand loop started one display frame later and then stopped: only every other frame drew (profile in docs/tasks/W1.01.md).

- **Lessons:** in a demand frame loop, schedule the next tick after signalling the render, or the render lands a frame late and halves the rate. Implementation by the implementer; report and commit by the lead after the guard hook blocked the report write.
