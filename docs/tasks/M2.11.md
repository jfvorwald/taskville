- **Lessons:**
  - Guarding against "repository config runs a program" one key at a time misses others. `core.fsmonitor` was blocked, but a partial-clone lazy fetch (`remote.<r>.uploadpack`) still runs from `for-each-ref`. Prefer environment kill switches (`GIT_NO_LAZY_FETCH=1`, `protocol.allow=never`) and a test repository built to be hostile.
  - A redactor that decides by the last word of a name misses compound and abbreviated names (`PGPASSWORD`, `MYSQL_PWD`, `*_PASS`). Test it against the real environment variables of common tools, not only against `*_PASSWORD`.
  - Two components that create the same directory need the same safety checks. The engine checks the home's owner and mode, but the installer and the shim do not, and they are the ones that put executable code in it.
  - A replay loop whose awaits never do real I/O does not yield. After listen, bound its work per tick, not only per run.

## Findings

| ID | Severity | Area | Summary |
| --- | --- | --- | --- |
| F1 | medium | Git watcher | Repository config runs any command during the read-only `for-each-ref` (partial-clone lazy fetch). The CLI token can register any directory as a root. |
| F2 | medium | Redaction | `PGPASSWORD`, `MYSQL_PWD`, `*_PASS`, `SECRET_KEY_BASE`, `mysql -p<pw>`, `sshpass -p`, `docker login -p`, and JSON name/value pairs reach the event log, `evidence.db`, and the install diff unmasked. |
| F3 | medium | Installer and shim | The Taskville home's owner and mode are not checked, so another local account that can write to it can swap the shim the hook runs. |
| F4 | low | Spool replay | The post-listen drain holds the event loop about 2.9 s per run. Live hooks posted in that window time out, are spooled, and replay as `late`. |
| F5 | low | Redaction | Known gap confirmed: a `-` before a token prefix blocks the prefix rules. The high-entropy fallback covers it except for runs over 256 characters or with low entropy. |
