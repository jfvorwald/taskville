## Composition with M1.07 (#9)

M1.07 was not merged when this branch was ready, so `reducer/index.ts` is not touched. Whichever ticket merges second wires the slice in:

```ts
// ProjectState gains top-level `requests` and `commands` (data-model.md names).
const slice = reduceRequests({ requests: state.requests, commands: state.commands }, event);
return { ...next, requests: slice.requests, commands: slice.commands };
```

`reduceRequests` returns the same object when the event has no effect, so the root reducer can skip copying in that case. For `since` on turn records, the selectors use `lastTurnAt` when the Agent has it and fall back to `lastSeenAt` otherwise. If M1.07 does not store a turn time, `since` on those records moves with every event from the agent.

## Rules as built

1. **Answerable** only when `sourceId === "taskville:bridge"` exactly and the event is not late.
2. **Merge (one prompt, one red state):** an open `permission` request with the same `sessionId`, `agentId` and `toolName` (two absent tool names count as equal). A request without a session never merges, and neither does a late one. Two bridge-held requests never merge, because each one holds its own hook response. When several records match, the earliest opened wins, then the smallest ID. The rule never depends on key order, so a projection restored from canonical JSON reduces the same way as a live one (tested). Merged IDs are kept in `mergedRequestIds`, and `request.resolved` or `request.expired` for any of them closes the record.
3. **Bridge record wins** when telemetry opened first. It takes over the record (its ID, preview, reason and expiry), keeps the earlier `openedAt`, and moves the telemetry ID into `mergedRequestIds`. This stops a forged telemetry preview from ever appearing on an answerable card. The rule is D3 in #135.
4. **Closure:** `tool_call.finished`, `session.turn_ended`, `session.turn_failed`, `session.prompt_submitted` and `session.ended` close every open request in the same session. The outcome is `answered_here` when a `succeeded` `permission.decide` command already targets the request (a `session.open` is not an answer), and `answered_elsewhere` otherwise. Events with no `sessionId`, and events outside that list (`tool_call.started`, `session.idle_prompt`, ...), close nothing. The first closure wins.
5. **Engine-only events** (`request.resolved`, `request.expired`, `command.*`) are applied only from a `taskville:` source. Ingest already enforces this, and the reducer checks it again.
6. **Late** `request.opened` is stored with `late: true`, `state: "expired"` and `answerable: false`. It never merges and never yields `needs_you`.
7. **Commands:** `requested -> delivered -> succeeded | failed | expired`, `requested -> unsupported`, and `requested -> failed | expired` (the request was closed, or the hold window ended, before delivery). `succeeded` requires `delivered`. Terminal statuses are final, a repeated `command.requested` is ignored, and `command.failed` keeps its `reason`. `reason` is a field added beyond data-model.md's Command list, because the event carries it.
8. **A repeated `requestId`** (its own ID or a merged one) is ignored, and the first record wins.
9. **Selectors:** `needs_you` comes from each open request. `stop_failure` comes from `lastTurn === "failed"`, `tool_failures` from `consecutiveToolFailures >= 3`, and `turn_ended` or `idle_prompt` from `lastTurn`. `silent` needs an agent that is connected and not finished, with no `needs_you` or `waiting` record, and with `now - lastSeenAt` greater than the threshold. It is labelled `heuristic: true` with the reason text `quiet for N min`. Records sort by level, then by `since` in real time (offset-aware), then by agent, kind and request ID. `attentionCounts` counts agents per level, not records. Every record parses with the protocol's `attentionSchema` (tested).
10. **Purity:** a new scan (`test/attention/purity.test.ts`) fails if `reducer/attention` or `selectors` read the clock or randomness (`Date.now`, `new Date`, `Date()`, `Math.random`, `performance.`, `crypto.`, `process.`). `Date.parse` of event timestamps is allowed. The existing Node built-in scan covers these directories too.

## Risks and follow-ups for the lead

- **Paths outside Owns:** `packages/domain/package.json` adds `@taskville/protocol` (`workspace:*`, the same line M1.07 adds) plus `exports` for `./reducer/attention` and `./selectors`, and `pnpm-lock.yaml` gains the matching 4 lines. Tests sit under `packages/domain/test/attention/`. If M1.07 merges first, the `package.json` and lockfile conflict is limited to the `exports` map.
- `test/attention/envelopes.ts` duplicates the small envelope builder that M1.07 adds in `test/reducer/events.ts`. Folding them together is a cleanup for after both merge.
- **Closure edge case (D2 in #135):** with the literal rule, a parallel tool call's `PostToolUse`, or another subagent's, in the same session closes a pending prompt as `answered_elsewhere`. If the Notification for that prompt arrives later, it opens a new unanswerable red record.
- **M2 adapter (#22):** the Notification has no tool name, so under D1's default the adapter must attribute `toolName` (S-1: shared `prompt_id`). Otherwise the PermissionRequest and its Notification show as two red records.
- Requests and commands are never pruned from state. That is fine for M1, but SC-006 bounded-state checks should keep an eye on it in long demo runs.

## Lessons

- Any rule that picks one record out of a map must not depend on key iteration order. A projection restored from canonical JSON has sorted keys, and integer-like IDs ("3" before "20") reorder even in a live object, so the merge target is chosen by `openedAt` and then ID. A canonical-JSON round-trip test pins this.
- Read literally, "the existing record is kept" when merging would let forged telemetry that arrives first supply the preview on an answerable card. Merge rules that combine a trusted source with an untrusted one need a direction-specific test.
