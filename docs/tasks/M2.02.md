## The route

- **Body:** exactly `{ sourceEventId, payload }` (the shim wrapper from the lead's notes for #20; #20's PR was not visible yet). `sourceEventId` is a protocol ID (1 to 256 characters), `payload` a JSON object. Any other key, including `late` and `__proto__`, is `400 bad_request`. Keys are read with `Object.hasOwn`, and an inherited `cwd` is not the hook's `cwd`.
- **Auth:** scope `ingest`, so the CLI token only; a browser session and the bridge token get `403 credential_not_allowed`. The shim sends a bearer token and no `Origin`, which the M1 Origin rules already allow for bearer requests (any `Origin` that is present must still be the engine's), so no rule was loosened and nothing was added to an allowlist.
- **Size:** 5 MB, the batch route's limit, `413 payload_too_large` before anything is parsed or mapped.
- **Response:** `200 { projectId, results, heads }` with the batch route's per-event results; `ignored: true` (the mapper's reason is not echoed) when the hook maps to nothing.
- **Pipeline, not around it (L-38):** every mapped event goes through `IngestPipeline.ingest`: validation, producer policy, masking, dedupe on `(projectId, "claude-code", sourceEventId)`, sequencing, one transaction. The engine overwrites `projectId`, `sourceId` and `late` on every mapped event, so the mapper cannot route to another project, claim a `taskville:` source, or set `late`.

## Idempotency

The shim's `sourceEventId` alone is the dedupe key for this source. A hook payload carries no timestamp, so the mapper's `occurredAt` comes from the engine clock (`ctx.receivedAt`), and a spool replay sets `late`; both are in the M1 pipeline's content hash, so without this a retry or a hook that landed live and was also spooled (the 1 s timeout fired after COMMIT) came back as `conflict` (roborev 5059, 5062). Before ingest the source looks up each mapped event's `(projectId, "claude-code", sourceEventId)`; one already in the log is reported `duplicate` with its original sequence and event ID and not re-sent, the rest go through the pipeline. Lookup and ingest run in one tick with no await between them. Trade-off: a reused UUID with a different payload is reported duplicate rather than conflict for this source; the UUID is the shim's, generated per hook. If routing changes between the live post and the replay (a project added in between), the lookup is in the new project and the hook is stored twice, once per project.

## `late`

Only `ClaudeCodeSource.ingestHook({ ..., late: true })` sets it, and that is the entry point the spool replay (#28, M2.07) is meant to call in-process at engine start. Over HTTP it is always `false`: the wrapper refuses a `late` key, so a holder of the shim token cannot mark a live prompt late to keep it from opening needs-you. (The generic batch route still accepts producer `late`, M1.12's recorded default; unchanged here.)

## Project resolution

- Projects come from the registry (`storage.projects()`, decision #110) on every hook, so a project added with `taskville project add` routes at once. The built-in Unsorted project is never matched, only fallen back to.
- `cwd` is untrusted. Anything that is not a string, absolute, at most 4,096 characters, well-formed UTF-16, and free of C0 or DEL control characters goes to Unsorted.
- Both `cwd` and the configured roots are normalized with `path.posix.normalize` (`.` and `..` resolved, never above `/`; repeated and trailing slashes dropped). A root matches when `cwd` equals it or starts with it plus `/`, so `/repo-evil` never matches `/repo`. The longest matching root wins; equal roots go to the smallest project ID.
- **Symlinks:** the path as Claude Code reported it is matched first, lexically, with no file system access. Only when that matches nothing does the engine call `realpath` on each root and then on `cwd`, and match again. That covers a root configured through a symlink and the macOS `/tmp` versus `/private/tmp` case, while a symlink inside a repository never moves a hook out of the project its reported path names. A path that no longer exists (a spooled hook replayed after the folder was deleted) falls back to Unsorted.
- Matching is case-sensitive, also on case-insensitive macOS volumes.

## Notes for related tickets

- **#20 (shim):** `400` and `413` from this route mean the body will never be accepted (malformed or too large), so spooling them only replays a failure; worth dropping those. `404` (an engine without this route, as now) along with connection failures and `5xx` should spool. The "unmounted is safer" argument below assumes the shim spools on `404`.
- **#22 (mapper):** the engine passes `ctx.sourceEventId` as the shim's UUID. One hook can map to several events, so the mapper must derive a distinct, deterministic `sourceEventId` per event (for example `<uuid>:<n>`), or the second is a dedupe conflict.
- **#27 (evidence):** the sink gets raw, unmasked tool input and output; it must redact before writing. It is called only when at least one of the hook's events is in the log (accepted or duplicate), after COMMIT; a throw is logged by name only.
- **Timestamps (#20, #22, #28):** hook payloads have no time field, so a spooled hook replayed at the next engine start gets that start time as `occurredAt` unless the shim records when the hook fired. Worth adding a capture time to the wrapper (and a matching `MapContext` field) so late events sit at the right place in history; this route refuses unknown wrapper keys today, so that is a coordinated change.
- **Session split risk:** routing is per hook, by that hook's `cwd`. If a session's `cwd` moves between roots (or out of all of them) mid-session, its events split across projects. ARCHITECTURE.md 8.1 describes per-directory routing, so this follows it; a sticky per-session project would be a separate decision.

## Lessons

- A placeholder mapper is worse than no route: the shim treats 200 as delivered, so wiring an incomplete source into `serve` would lose events that an unmounted route (spooled 404) keeps.
- `late` belongs to the transport, not the body. Making it reachable only through an in-process call, not a wrapper field or a header, removes the need to authenticate who may set it.
