## What changed

- `apps/engine/src/commands/open-session.ts` (new): `openSession(request, { config, execFile, isDirectory? })`, result and dependency types. Copy-only when `config.sessionOpener` is null; otherwise `renderOpener` then `execFile(file, args, { shell: false, windowsHide: true })`. Only `sessionId` and `cwd` are read from the request, so a template on the request is ignored. A rejected value gives `invalid-value`; a spawn error or non-zero exit gives `spawn-failed` with only the code in the message (never raw error text, arguments or cwd).
- Fix round: `createDefaultExecFile({ graceMs? })` (default 2000 ms) and `defaultExecFile = createDefaultExecFile()`. It spawns with `shell: false`, `windowsHide: true`, `stdio: "ignore"`, `detached: true`; resolves when the child survives the grace window (then `unref()`s it and leaves it running) or exits 0 inside it; rejects with an error whose `code` is the non-zero exit code or the spawn error code (such as ENOENT). A no-op-after-settle `error` listener stays on the child so a late error cannot crash the engine; the grace timer and exit listener are cleared on settle.
- Fix round: `defaultIsDirectory(path)` (`fs.stat`, false for files and missing paths, never throws) and optional `OpenSessionDeps.isDirectory`. When supplied and false, `openSession` returns `invalid-value` and runs nothing. The check applies only when the template uses `{cwd}` (roborev job 5758 finding: a `{sessionId}`-only opener must still work for a session with no working directory). The doc comment on `isDirectory` says M4.03 must pass `defaultIsDirectory`.

## Handed to M4.03

- Pass `isDirectory: defaultIsDirectory` when wiring `openSession`.
- Take the cwd from the recorded session, not from the request body.
- Cap the number of in-flight openers.
- Add a behavioral case for a template without `{cwd}` and a session with no working directory; it is not in this ticket because the tests were frozen in the fix round.
