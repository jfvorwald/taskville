## Contract for #21 (hooks endpoint) and #28 (spool ingest)

The authoritative text is the header of `apps/cli/hooks/claude-code-shim.sh`. In short:

- **Request:** `POST /v1/sources/claude-code/hooks` with `Authorization: Bearer <$TASKVILLE_HOME/token>` and `Content-Type: application/json`, and no `Origin` or `Expect` header. The body is `{"payload":<hook JSON>,"sourceEventId":"<lowercase uuid v4>"}`, keys in that order, so a malformed payload can never override the ID under `JSON.parse` last-wins. Any 2xx counts as success; anything else spools the event. URL: `TASKVILLE_URL`, else `http://127.0.0.1:4807`. Only `http://127.0.0.1:<port>` or `http://localhost:<port>` is ever contacted.
- **Spool:** the directory is `$TASKVILLE_HOME/spool` (0700), with files 0600. The main file is `claude-code.jsonl`. When the lock is busy for about 1 s, or the main file is a symlink, not a regular file, or owned by someone else, the event goes to its own file, `claude-code.<sourceEventId>.jsonl`. Dot files (`.claude-code.*`) are in-progress temporaries and must never be ingested. Each line is `{"payload":<hook JSON>,"sourceEventId":"<uuid>","spooledAt":"<YYYY-MM-DDTHH:MM:SSZ>"}`. Unparseable lines must be skipped. A reader that renames or truncates `claude-code.jsonl` must hold the lock: `mkdir claude-code.lock`, write its PID to `claude-code.lock/pid`, and remove the directory when done.
- **Limits:** the cap is 5 MiB less 1 KiB (5,241,856 bytes) of raw hook JSON, set by the endpoint's 5 MiB body limit. A bigger payload is not posted. It is spooled as `{"payload":null,"payloadBytesAtLeast":<n>,"sourceEventId":...,"spooledAt":...}`, and spool ingest has to record or skip that marker.
- **Sensitivity:** the spool holds unredacted payloads (prompts, tool inputs and outputs). The engine masks them at ingest.
