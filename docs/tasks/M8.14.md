- **Lessons:** Check budgets per body, not per import: staged bodies are all ahead of the store, so a whole-import check admits them all. Credit freed room only after the delete that frees it succeeded. Keep pointers while an archive row can still be listed, so its bodies read as evicted instead of missing. Never delete old evidence before the replacing archive is committed: a failed write then costs the old archive its evidence.

## What changed

- `EvidenceStore.fitArchiveEvidence` checks each incoming body, in order, against the archive budget left (stored bytes, no sharing between bodies, so the total never passes the cap). Bodies that do not fit are dropped and counted in `evidenceDropped`; smaller ones after them may still be stored.
- The import order is now: commit the new archive (row and events); delete the evidence of archives beyond retention; fit and store the new archive's evidence, crediting only deletions that succeeded; record the dropped count with `archives.updateCounts`; then delete the pruned rows and their pointers. Nothing old is touched if the archive write fails.
- `archives.updateCounts(id, counts)` (`apps/engine/src/storage/archives.ts`, outside the ticket's Owns, approved) replaces the counts of a `done` archive, since the dropped count is only known after the commit.
- `archiveEvidenceFull` no longer takes an `excluding` list.
- `deleteArchive` takes `{ keepPointers: true }`: bodies and usage go, pointers stay, so a done archive whose row deletion then fails reads its bodies as evicted ("details no longer stored"). The importer removes the pointers once the row is gone.
