## What changed

- **F4, `apps/engine/src/auth/pairing.ts`:** exports `PAIRING_CODE_TTL_MS` (10 minutes). `issueCode()` records the issue time and `exchange()` rejects a code once `now - issuedAt >= TTL`, dropping it for good, so a clock that goes back cannot revive it. The clock is a `now` option in milliseconds, which defaults to the monotonic `performance.now()`, so a wall-clock change cannot extend a code. Sessions already paired are unaffected. The exchange attempt limit mentioned in the finding is not added: the fix the review named is the TTL, and a 256-bit code is not guessable.
- **F6, `apps/engine/src/config/opener.ts`:** `renderOpener` throws the new `OpenerValueError` when a placeholder the template uses has a value that could become an option: `{cwd}` must be an absolute path (`node:path` `isAbsolute`), and `{sessionId}` must match `[A-Za-z0-9][A-Za-z0-9._-]*`. Unused placeholders are not checked, so a template without `{cwd}` works for a session with no working directory.
- **Forced extra, `apps/cli/src/commands/serve.ts`** (lead's request): the pairing line now reads `Pair a browser (one-time link, valid for 10 minutes): <url>`, computed from `PAIRING_CODE_TTL_MS`. `apps/cli/test/integration.test.ts` asserts it. No golden file holds serve output.

## Lessons

- A reviewer applied PCRE semantics to JavaScript (`$` matching before a trailing newline). A one-line `node -e` settled it faster than arguing from documentation, and the test row for that exact input was already there as evidence.
- Default the expiry clock to a monotonic source (`performance.now()`) rather than the engine's injected wall clock: tests still inject time, and a TTL meant to shorten exposure cannot be stretched by a clock change.
