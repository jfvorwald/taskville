Failing (the real red set):
- `never raises a connection whose own busy_timeout is smaller than the budget`: 325 ms vs under 150. A connection opened with `busyTimeoutMs: 30` is raised to the 250 ms budget; use `Math.min(ownTimeout, remaining)` in `#limitWait`.
- `prune returns 0 promptly while a foreign connection holds the write lock`: throws "database is locked" after the wait. Prune must probe read-only (`SELECT 1 ... LIMIT 1` with the same predicate) and return 0 without `BEGIN IMMEDIATE` when nothing matches.
- `a seek over a fully populated, healthy cache is not delayed by a foreign write lock`: 325 ms vs under 100, same cause.
- `a row whose state.head is not the row's sequence is ignored` and `a row whose state.projectId is not the row's project is ignored`: a self-consistent forged row is trusted and the result differs from a full replay. `trusted()` needs `state.head === row.sequence` and `state.projectId === projectId` (pass the project id in).
- `boot writes checkpoints...` three tests: `a boot rebuild leaves a trusted checkpoint at every multiple of 500` (got `[]`), `a seek right after boot replays at most 250 events` (1250 applied), `the first boot after a reducer version change writes checkpoints for the new version` (got `[]`). `rebuildProjection` / `rebuildStaleProjections` in `apps/engine/src/storage/rebuild.ts` must write a checkpoint (via `tx.writeCheckpoint`, inside its transaction) at each multiple of `CHECKPOINT_INTERVAL` while it folds, for every project it rebuilds, using `reducer.version`.
