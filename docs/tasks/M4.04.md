- **What changed:**
  - `apps/engine/src/bridge/wire.ts` (new): `wirePermissionBridge` composes the bridge (hold window from `bridge.holdWindowSeconds`), the command service (opener from `sessionOpener`, default detached `execFile`), and registers the bridge, command, and input routes. Returns `{ bridge, commands, observeHook, close }`.
  - `apps/engine/src/bridge/input-route.ts` (new): `GET /v1/requests/:requestId/input?projectId=`, `command` scope (paired browser only). Builds its two error bodies locally because the shared `ErrorCode` union in `http/errors.ts` is outside this ticket's paths.
  - `apps/engine/src/bridge/bridge.ts`: `HeldRequest` and `lookup` carry the hook's `cwd` when it is a string.
  - `apps/engine/src/sources/claude-code/route.ts`: `registerClaudeCodeRoutes(app, source, { observeHook })`, called after events commit, only for a non-ignored response with at least one `accepted` result; a throwing observer is swallowed without logging (the error could echo hook content).
  - `apps/engine/src/config/config.ts`: `MAX_HOLD_WINDOW_SECONDS` 600 to 300.
  - `apps/cli/src/commands/serve.ts`: wires the bridge and commands, passes `observeHook` to the telemetry route, closes the bridge first on shutdown so no held hook blocks the server close. A bad hold window is already refused by `loadConfig` at start.
  - `apps/cli/src/commands/install.ts` and `install-settings.ts`: the PermissionRequest `http` hook; the config is now always read (so a bad value stops the install and the timeout is hold window + 5 even with `--url`); an unchanged entry is "already installed", a narrowed or edited one is replaced; uninstall removes only an `http` hook whose URL is a loopback origin plus the exact bridge route (the byte-for-byte restore rebuilds the bridge entry too); output names `TASKVILLE_BRIDGE_TOKEN` and `<home>/bridge-token` and never the token.
  - `specs/001-headless-foundation/contracts/http-api.md`: the input route, hold window range, and installed hook.

  - `taskville install claude-code` now fails with `cannot read the Taskville config` when `config.json` is unreadable or invalid even if `--url` is given (previously `--url` skipped the config).
  - Port squatting (security review medium, decision #284): while the engine is not running, another local identity that binds the engine port receives the bridge token and each request's exact tool input and can answer `allow`. Accepted as a residual for a single-user machine (same-user attackers can already edit settings); the telemetry shim has the same port exposure with only the CLI token. A response-signature check needs a design ticket.

  - `uninstall` still recognizes an older entry that used `localhost` (the URL match accepts either loopback host) so an install made before #284 is removed.
  - "Already installed" compares the bridge entry to the exact JSON the installer writes (key order included), so a user who reordered its keys gets a reinstall diff.
