## What was built (`apps/web/src/city/interaction/`)

| File | Role |
| --- | --- |
| `selection.ts` | `selectionStore`: `{select, getSnapshot, subscribe}`, so it is an M3.03 `Selector<string \| null>`. Agent ids are plain; a building is `area:<areaId>` (`areaSelectionId`, `parseSelectionId`). The M3.02 store shape is untouched. |
| `useSelection.ts` | `useSelection()` returns the overlay host's `OverlaySelection` (`{selectedId, select}`) over that store. |
| `cameraRig.ts` | `cameraRig`: turn (degrees, wraps) and zoom factor (0.6 to 3), `orbitBy`, `zoomBy`, `reset`. Pure state. |
| `CameraDriver.tsx` | Applies the rig to M3.04's camera each frame. Turn rotates the camera about the vertical axis through the city center; zoom multiplies the fit zoom. At the default view it writes nothing. |
| `pick.ts` | Raycast picking. `collectPickables` finds agent groups (`userData.agentId`, M3.05) and `building-<id>` groups (M3.04) a few levels deep; windows, scenery and ground are never tested. `createPicker` reuses its raycaster and arrays. |
| `hull.ts` | Hover rim glow: a pooled inverted hull (back faces, flat color) under every mesh of the hovered target, constant thickness whatever the part size or agent scale. No bloom. |
| `occlusion.ts` | Which buildings sit between a point and the camera (ray against each footprint box, scalars only) and an easing step. |
| `fade.ts` | Fades whole buildings: swaps a per-building clone of each shared material in while it is see-through, restores the shared material when solid, and scales that building's window instances to nothing while it is faded. Re-reads the shared materials at fade time, so a theme change in between is safe. |
| `InteractionLayer.tsx` | Mounted in `CityRoot`. Pointer events on the canvas: hover glow and pointer cursor, click selects (empty ground or Escape clears), drag turns, wheel zooms. Selection marker (ground ring for an agent, square ring for a building). Selecting an agent fades the buildings that hide it; faded buildings are looked through for hover and click. |
| `CameraControls.tsx` | A header-slot overlay (`cameraControlsOverlay`): turn left and right, zoom in and out, Reset view. Its wrapper carries `data-azimuth-offset`, `data-zoom` and `data-selected-id` for automation. |
| `fixture.ts` | Test aid. With `?tv-fixture=agents` in the URL, two fixed agents are mounted (M3.05 `AgentsLayer`) and `window.__tvProbe(anchorId)` reports where the live camera puts a fixture point. Inert otherwise. |

No per-frame allocation in the frame loop: transforms, ray math and fades use module scratch objects; the parsed selection is cached on change. Work that does allocate runs only on events: a pick (three.js allocates its hit points) on a pointer move that changed target, and a re-scan for a lost selected agent at most every 0.5 s.

## Review fixes since fadcc18

Code review and the confirm review each produced findings; tests first, then source (commits 5c631f5 and 405d84a, then 17de202 and the fix on top of it).

- **Theme change mid-fade:** the fader adopts a replaced shared material while a building is faded (fresh clone at the current opacity, old clone disposed, new shared material never disposed).
- **Theme change while solid (confirm review):** the first fix kept stale clones of the old theme, so the next fade-out showed the old colours. A solid building whose shared material changed now disposes and drops its clones; the next fade-out clones the new materials. No allocation per frame when nothing changed.
- **Rescan clear:** a selected agent that is lost is cleared (InteractionLayer, with a browser test).
- **Reduced motion:** `setSeconds` changes the fade duration at runtime (0 is instant).
- **Camera remount:** `cameraPose.ts` tracks the camera's default pose so a remounted `CameraDriver` still resets. The default pose is kept per camera (module-level `WeakMap`), not per tracker, so a fresh tracker on an already turned camera resets to and turns from the original pose (confirm review).
- **Escape guard** (`escape.ts`) and **pointercancel** handling (`pointer.ts`, `selection.ts`).

## Findings for the lead

1. **The live camera looks at the origin, not at `CITY_CAMERA.target`.** `SceneRoot`'s `onCreated` calls `camera.lookAt(0, 0, 0)` after `CityCamera` aimed at `(0, 1.5, 0)`, so `projectToScreen` (and anything built on its assumption) is about 21 px (at 1280x720) off vertically from what is drawn. I measured it by reading the camera at runtime. `CameraDriver` does not depend on either: it reads the pose the camera has and rotates it. The e2e test uses the real projection through `worldAnchors` instead of `projectToScreen`. Not mine to change (M3.01 and M3.04 paths).
2. The drei `OrthographicCamera` and a resize: `CameraDriver` re-applies the zoom factor on every size change, so Reset and zoom survive a window resize.

## Lessons

- A test that derives a screen position from the camera math can pass against the wrong camera: here the math and the drawn camera disagree. Ask the running scene where a point is (the anchor projection) rather than recomputing it in the test.
- Three.js `Raycaster` needs `matrixWorld` current: unit-test scenes must call `updateMatrixWorld(true)` or every object tests at the origin, and a pick can pass by coincidence.
- Fading one building when all share per-tone materials: clone per building on first fade and swap, instead of changing the shared material. Instanced windows cannot be faded per building; scaling a building's instances to zero is the cheap answer.
- On macOS, `sed -i` needs an empty suffix argument (`sed -i ''`); without it, the next path is read as the script.
- First paint of the WebGL canvas can exceed Playwright's default 5 s when other workers load the machine: give the first `toBeVisible` on the canvas a longer timeout.
