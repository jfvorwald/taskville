## Contract (written first, L-30; `specs/001-headless-foundation/data-model.md`)

- **Unfinished tool calls.** A running call is closed with phase `unfinished` (domain only, never an input value), with `finishedAt` set to the closing event's time. The first of these closes it:
  - the owning agent's own `session.turn_ended`, `turn_failed`, `prompt_submitted` or `session.ended` in the call's session, or its `agent.finished`;
  - for an unregistered agent (S-2 helpers), the same boundary events from the agent that owns the call's session;
  - `session.ended` of the call's session, from any agent.

  A registered agent's running call is never closed by another agent's turn: background subagents keep running after their parent's Stop.

  Closing changes no counter and does not clear `lastTurn`. A later `tool_call.finished` replaces `unfinished` with the recorded result. Retention is unchanged: at most 32 running calls plus the latest finished call per agent, and when one boundary closes several calls, the latest started one is kept.
- **Session ownership.** A registered `subagent`, or an agent of the nested Claude Code form `claude-code:<session>:<agent>`, never owns a session. That covers in-process teammates, helpers, and subagents whose registration has not arrived. A split-pane teammate has its own session ID and keeps its session, so "teammates never own a session" is applied by the ID form rather than by kind.
- **Teammate turns.** A `teammate`'s ended turn raises no `waiting`. It is still treated as waiting for the silent check, so an idle teammate is never shown as silent trouble. This lives in the attention selector, so it holds whichever arrives first, the Stop or the registration.
- **Request closure, decision #184 D1** (`closesRequest` in `reducer/attention/requests.ts`):
  - A telemetry request closes only on its owning agent's events, or on `session.turn_ended`, `session.prompt_submitted` or `session.ended` from any agent.
  - A bridge-held request is never closed by a same-session event. Only the engine closes it: a matching PostToolUse or a closed hook (M4), `request.resolved`, or `request.expired`. This is decision #116, `.roborev.toml` invariant 4.
  - The #184 alternative is a one-line change, documented in the function's comment.

## Honest in the CLI

`taskville status` renders no tool-call phase. An `unfinished` call changes no counter `status` reads, so a lead whose three calls were denied shows `waiting`, never `trouble`. A split-pane teammate's ended turn shows no `waiting`. Both are pinned in `apps/cli/test/real-sessions.test.ts`.

## For the lead

1. **S-1 exp6 stays running in the recording.** It is the last hook of its session: the spike moved to a second session and had no SessionEnd hook. With the real install (which registers SessionEnd), `session.ended` closes it. The stream test pins this fact.
2. **Bridge requests and M4.** With this PR, nothing in the reducer closes a bridge-held request except engine events. M4 must emit `request.resolved` for the matching PostToolUse (#116 D3), the closed hook (D2), and the hold window end. Otherwise a bridge request stays red until it expires at engine start.
3. **Generic-source ownership (roborev 5249 medium, answered).** For a non-Claude source, a subagent that names a session before its registration arrives still owns it. Handing the session back needs a rightful owner, which the stream does not name. This is out of this ticket's Claude Code scope; a follow-up could add an adapter-provided "nested" flag instead of the ID form.
4. **data-model.md** now documents `unfinished`. The web client (M3, M5) should show it as "no result recorded".

## Lessons

- An invariant written in `.roborev.toml` decides a review, even when the decision ticket (#184) speaks only of telemetry requests. I relaxed bridge requests from "any agent" to "owner only" and was still wrong: #116 says no same-session event closes them at all. Read the review guidelines for the rule before narrowing it.
- Recorded streams carry surprises a unit test would not. S-1's exp6 is the last hook of a session that never ends in the recording, so "no call running after the turn ends" has to be checked per session.
- A projection rule keyed on an adapter's ID format (`claude-code:<s>:<a>`) is a pragmatic seam, but it should become an explicit field the adapter sets.
