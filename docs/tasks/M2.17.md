## The rule

`redactJson` (the one shared rule for ingest and evidence) now masks every scalar anywhere under a sensitive property name (`password`, `apiKey`, `token`, ...), at any depth:
- Strings, numbers and booleans become `[REDACTED:sensitive-value]`, inside nested objects and arrays too. This covers objects inside an array under a sensitive key, which the old rule reset to their own keys.
- `null` stays `null`, since it carries nothing.
- Complete references such as `$DB_PASSWORD` stay readable at any depth, as they already did directly under a key.
- `skip` (the unmasked ID, enum and timestamp fields) is respected at any depth.
- `__proto__` stays data.
- Each masked scalar gets its own mask entry, with its path.

The evidence-only version from M2.06 (`maskSensitiveSubtrees` in `apps/engine/src/evidence/body.ts`) is removed, and evidence now calls the shared rule. One visible change: an evidence body keeps its shape, for example `{"password":{"value":"[REDACTED:sensitive-value]"}}`, instead of a single marker replacing the whole subtree. The masked flag works as before.

## Old events and the dedupe hash

- **Event log:** no stored event can be affected. Every payload a producer may send is a strict schema with no sensitive-named field and no free-form object. The one free-form object, `command.requested.payload`, is engine-only, and the pipeline rejects it from every source until M4. So the masked payload of every event ingested before the fix is unchanged. A retry hashes the same and is a `duplicate`, never a `conflict`. The fix matters for M4, when the engine writes `command.requested`, and for evidence today.
- **Evidence:** a body is stored once per tool call and part, and the first write wins. A retried hook after the fix keeps the earlier body: no conflict, no error. Bodies stored before the fix were already fully masked by M2.06's subtree rule, so nothing old needs scrubbing. A body with a nested sensitive value now hashes differently than it did under M2.06. That only affects content-addressed sharing between old and new bodies, which is a storage-size effect, not a correctness one.
- **Spool:** events spooled before the fix are mapped and masked when they are replayed, so the new rule applies to them.

## Lessons

- A redaction rule written as "the value of a sensitive key" has to say what happens to non-strings and to what is below the key. The table of nested, array, number and boolean rows is the spec.
- Before documenting a hash migration, check which payloads can actually carry the shape. Here the strict schemas meant no stored event could change.
