## What the module does

`@taskville/adapters/redact` exports:

- `redactText(input)` returns `{ text, spans }`. Each span is `{ kind, start, end, maskedStart, maskedEnd }` in **UTF-16 code units** (JavaScript string indices), half-open. `start`/`end` locate the secret in the original input (for click-to-reveal from the unredacted in-memory copy); `maskedStart`/`maskedEnd` locate its marker in the masked text. Spans are sorted and never overlap: overlapping detections are unioned and keep the most specific kind.
- `redactJson(value, { skip })` returns `{ value, masks }`, where each mask is `{ path, spans }` for one string that changed. Every string at any depth is masked; `skip(path)` lets the ingest pipeline exempt ID, enum and timestamp fields (contracts/events.md "Masking"). Property names, numbers, booleans and null pass through, and the input is not mutated.
- `maskMarker(kind)` gives the replacement text, `[REDACTED:<kind>]`.

Masking is pure and deterministic (no clock, randomness or I/O) and idempotent (masked output has nothing left to mask), so a retried event masks to the same text and still dedupes. Truncation to 280 characters is the caller's job and happens after masking, per FR-017 and research.md R-13.

Detected: Anthropic, OpenAI, GitHub (classic, OAuth, fine-grained), AWS access key IDs, Slack, Stripe secret and restricted keys, JWTs, `Bearer` and `Authorization: Basic` credentials (case-insensitive), PEM private key blocks (an unterminated block is masked to the end), passwords in URLs, values of sensitive names (`*_TOKEN`, `*_SECRET`, `*_PASSWORD`, `PASSPHRASE`, `*_CREDENTIALS`, `*_PAT`, `Authorization`, upper-case `*_KEY`, and `apiKey`/`private_key`-style names with a qualifier) in `NAME=value`, `name: value`, `"name": "value"`, `--name value` and query-string forms, and high-entropy tokens both when assigned and when standalone in prose.

Kept readable (false-positive tests): Git SHAs, UUIDs, base64 images (data URIs and raw PNG/JPEG/GIF/WebP/SVG prefixes, and anything over 256 characters), lockfile integrity digests, POSIX and Windows paths, `KEY_FILE=`/`TOKEN_PATH=` paths, code such as `const token = await getToken()`, `$NAME`/`${...}`/`$(...)` references, `***` placeholders, camelCase identifiers, Claude Code `toolu_`/`msg_` IDs, and prose that talks about tokens and passwords.

## Choices worth a look

- **Fake secrets in tests** are built at runtime from short string parts and a seeded LCG, so no token-shaped literal is in the source for GitHub push protection or other scanners to match.
- **Looser forms need evidence.** `NAME=value` and quoted values under a sensitive name are always masked. `name: value`, `name = value` and `--name value` unquoted are masked only if the value looks like a credential (letter and digit, 6+ characters, no code or path punctuation) or is high-entropy, so `Password: required` and `token = getToken()` stay readable. Cost: `password: correcthorsebattery` (letters only, unquoted YAML) is not masked.
- **Upper-case `*_KEY` is always sensitive** (the brief's rule), so `const CACHE_KEY = "users"` is masked. Mixed-case `*Key` names need a qualifier (`api`, `private`, `secret`, `access`, `client`, ...), so `cacheKey`, `sortKey`, and `idempotencyKey` stay readable.
- **Generic high-entropy rule** needs 20 to 256 characters, upper and lower case and a digit, entropy at least `min(0.85 * log2(length), 4.5)` bits per character, and less than 70% of the run in word-like runs. Measured on 5,000 random base62 strings, the word-run cutoff rejects about 1% at length 20 and fewer at longer lengths; identifiers such as `handleSubmitButtonClick1` are rejected.
- **Linear-time scanning.** Every token pattern starts with a lookbehind so it can only begin at the start of a run, quoted values stop at their closing quote or line end, and unquoted value ends (word end and next comma or bracket) come from one precomputed backward pass. 23 adversarial inputs of 100,000 characters each run in milliseconds. The adversarial test earned its keep: one fix scanned each value for a comma and took 55 s on `a=a=a=...`.

## Notes for the ingest pipeline (#13)

- Control-character stripping (events.md "Masking") is not in this module; do it before calling `redactText`/`redactJson`, so offsets refer to the normalized text.
- Cutting at 280 characters may split a marker (`[REDACTED:github-to`). Nothing leaks, but the UI should not assume markers are whole in truncated text.
- Two different secrets in the same place mask to the same text, so two such events with the same source key are a duplicate, not a conflict (accepted in research.md R-13).

## Lessons

- A redactor's skip rules are bypass surface. Every "this is a placeholder" exemption (`$` prefix, marker prefix, path-like runs) drew a high finding until it was made exact: a placeholder must be a complete reference or marker spanning the whole value, and the value has to run through any reference it starts with.
- Masking JSON loses the property-name context in arrays unless the walker carries it down, and plain assignment of a parsed `__proto__` key changes the prototype. Use `Object.defineProperty` when rebuilding objects from untrusted JSON.
- A timing assertion tight enough to look meaningful alone (250 ms) flaked once the workspace had 21 test files running in parallel. Set wall-time bounds to separate linear from quadratic (seconds vs tens of seconds), not to measure speed.
- Entropy alone cannot tell a random token from a long camelCase identifier (both reach about 4 bits per character at 24 characters); a word-run coverage check separated them.
