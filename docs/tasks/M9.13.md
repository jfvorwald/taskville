- **Root cause:** `useBreakPlan` kept the 1 s tick as a state counter, so every tick re-rendered each consumer (CityAgents, Bubbles, PresentedSidebar) even though `samePlan` kept the plan identity. In CityAgents the re-render re-applied props to the R3F tree, and each commit that applies props makes R3F call `invalidate`, so an idle city drew about 1 frame per second.
- **Fix:** the tick now samples the plan inside the timer callback (from the latest render's inputs and a fresh `store.now()`) and sets state only when `samePlan` says the plan changed. Idle ticks cause no render and no frame. The clock is still read only in the callback or when a tracked input changes (M9.14 invariant); a bailed-out render sees the same `tick` and so the same plan.
- **Lessons:** a coarse tick that drives a derived value should compare outside React and set state only on change; a state counter re-renders every consumer whether or not the value moved. Count `invalidate` calls to catch render costs that pixels do not show.
