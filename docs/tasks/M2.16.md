## Contract (written first, L-30; `specs/001-headless-foundation/data-model.md` "Retention")

`retain` is the last step of `reduce` (`packages/domain/src/reducer/retention.ts`). After every event:

- **Finished agents** beyond the newest 50, by `finishedAt` then ID, are dropped. An agent is never dropped while any of these holds:
  - an unfinished agent names it as parent;
  - it leads a team that has not ended;
  - it has an open request;
  - it has a running tool call.

  A dropped agent takes its activity, tool calls, sessions and team places with it.
- **Terminal tasks** beyond the newest 50, by `updatedAt`, are dropped.
- **Closed requests** beyond the newest 50, by `openedAt`, are dropped.
- `retired { agents, tasks, requests }` counts what was dropped, so totals stay countable.

The rule reads only state, never a clock, so replay and a JSON checkpoint resumed at any point give the same `stateHash` (tested at four cut points). A later event that names a dropped record is applied like one for a never-seen record.

`REDUCER_VERSION` is now 5, in the single constant in `packages/domain/src/reducer/index.ts`, which M2.18's projection cache reads. #201 took version 4 while this was in flight.

## Lessons

- Bounding state did not bound RSS. The lively run went from +20% to +29% growth down to -26%, but the calm run stayed noisy at +18% with state flat from hour 6. Measuring state size and RSS side by side (the soak table already had both) kept the conclusion honest.
- The retention rule needed protections the ticket did not list (a live child's parent, a team lead, open requests, running calls). Each one was found by asking which reducer rule would later look the record up.
