## What changed

Owns:

- `apps/engine/src/stream/attention.ts` (new): `AttentionFeed` (recomputes the projects a commit wrote to, and all projects on a timer, using the injected clock; remembers the last announced record keys per project and notifies only when agent, level, kind or request ID changes; does no work with no listeners; a new listener recomputes first so its snapshot and later frames agree), `AttentionSubscriber` (bounded queue, heartbeat `{}`, ends the stream on overflow so the reconnect gets a fresh snapshot) and `registerAttentionRoute` (`GET /v1/attention/events`, `read` scope, the stream cap, `pairing.onRevoke` for browser sessions, `hub.track` for shutdown).

## Project switching

It was small and contained. `useDataSync(projectId)` already restarts its sync loop (and `store.reset(projectId)`) when its `projectId` changes, so the only change is where the id comes from: `projectSelection` in `apps/web/src/data/project.ts` instead of a constant. No change to `store.ts`, `sync.ts` or `react.ts`. Not verified in a browser: that the 3D city and the selection reset cleanly across a switch (`reset` clears the selected agent). Because there is no project switcher yet, a chip is the only way into another project, so the header shows "Back to Unsorted" while away (added after roborev 5812 finding 2); a real project list/switcher is a separate ticket.
