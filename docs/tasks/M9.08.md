- **Lessons:** `useBreakPlan` computes the plan in render (so the first render is right, which history placement needs), re-renders on a 1 s tick and on store, setting and lighting changes, and keeps the same plan object while nothing in it changed, so consumers do not rebuild each second. Night is a function of the moment (lighting setting, else the cycle at that time). `buildModels` takes optional `breaks` and `breakSpots`, which add `breakSpot` to intents and `breakActivity` to the attention view (waiting only), which `useAttentionMarks` passes to `attentionEmote`. Navigator changes: a new `returnProgress` on `NavAgent` (0 at the bar to 1 at the workstation, only on the walk back from a bar break) drives `wobbleOffset` in `CityAgents.publishPositions`, which is 0 under reduced motion and allocates nothing; and an agent with no area (a waiting agent that was never given a workstation, such as one a remounted history city starts with) now goes straight to its break spot and, when the break ends, walks back to the plaza (new `home` goal) instead of staying at the spot. `useAttentionMarks.ts` (under `city/attention`) was touched because it is where the emote is chosen. Both the live and presented agent panels get `onBreak` through `PresentedAgentPanel`.
