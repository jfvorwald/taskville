### Interfaces for the implementer

Cost lives in a read endpoint backed by an in-memory ledger, not in the event log or `ProjectState`: no protocol or reducer change was needed. (Persistence across an engine restart and the retro report feed are NOT covered by these tests; see Open points.)

Engine, new module `apps/engine/src/sources/otlp/index.ts`:

- `registerOtlpRoutes(app: Hono<AppEnv>, options?: { ledger?: CostLedger }): CostLedger` registers all three routes and returns the ledger. The smallest edit outside Owns is calling it from `taskville serve` after `bootEngine`.
- `POST /v1/otlp/v1/metrics` and `POST /v1/otlp/v1/logs`: scope `ingest` (CLI token only; bridge token and browser session get 403 `credential_not_allowed`), 5 MB limit via `MAX_BATCH_BYTES` (413 `payload_too_large`), JSON only (415 `unsupported_media_type` for anything else, e.g. protobuf), 400 `bad_request` for malformed JSON or a body that is not an object, or whose `resourceMetrics` / `resourceLogs` is not an array. Error text never echoes the input. Success is `200 {}`. Unknown metric names, unknown log events, unknown `type` values, data points without `session.id`, and empty exports are ignored with 200.
- `GET /v1/agents/:id/cost`: scope `read` (CLI token and paired browser session). `200 { agentId, parentAgentId?, tokens: { input, output, cacheRead, cacheCreation }, costUsd }` or `404 { error: { code: "no_cost" } }` when no telemetry named the agent. It does not resolve a project; the ledger is keyed by agent ID.
- Attribution: agent ID is `claude-code:<session.id>` without `agent_id`, else `claude-code:<session.id>:<agent_id>`. `parent_agent_id` is reported as `parentAgentId` only; cost is never rolled up into the parent. Metrics are deltas and sum across exports. `claude_code.token.usage` maps its `type` attribute (`input`, `output`, `cacheRead`, `cacheCreation`); `claude_code.cost.usage` is USD. int64 values arrive as strings or numbers; doubles as numbers.
- Logs: `claude_code.api_request` records (attribute `event.name`) carry `cost_usd`, `input_tokens`, `output_tokens`, `cache_read_tokens`, `cache_creation_tokens`, plus `session.id`, `agent_id`, `parent_agent_id`. Rule so spend is not counted twice: an agent with any token or cost metric reports metric totals only; an agent with logs only reports the sum of its `api_request` records. Order of arrival must not matter (tested both ways).

Web, new files under `apps/web/src/overlays/agent-panel/cost/` (the implementer makes the smallest edit in `shell/AgentPanel.tsx` and the app wiring):

- `AgentPanel` gets an optional prop `costSource?: (agentId: string, signal: AbortSignal) => Promise<{ tokens: {...}, costUsd: number } | undefined>`. Absent source, `undefined`, or a rejection means nothing is shown. Stale answers for a deselected agent are dropped. The default source reads `GET /v1/agents/:id/cost` with the session header (404 becomes `undefined`).
- Markup inside `<header>`: `agent-panel-cost` containing `agent-panel-tokens` (`12.3k tokens`, `1k tokens`, raw counts in `data-input`, `data-output`, `data-cache-read`, `data-cache-creation`) and `agent-panel-cost-usd` (`$0.42`, `<$0.01`, `$0.00`). Helpers `formatTokens` and `formatCostUsd` in `cost/format.ts`. Token count shown is the sum of all four types.

CLI (`apps/cli/src/commands/install.ts` and the settings builder): `--otel` flag on `install claude-code`, added to the existing plan so the hooks are still written and the same diff, confirmation, `--yes`, `--dry-run`, atomic write and backup rules apply. Pinned `env` keys and the endpoint rule are listed at the top of `apps/cli/test/install/otel.test.ts`. The CLI token is never written: the credential goes through Claude Code's `otelHeadersHelper` setting, a command that prints the headers as JSON, pointing at a script in `<home>/hooks/` that reads `<home>/token` (like the shim). The test checks only that `settings.otelHeadersHelper` is a string, that no `OTEL_EXPORTER_OTLP_HEADERS` or `Authorization` is written, and that the token appears nowhere.

### Open points (not decided by tests; the lead should decide or confirm)

- `otelHeadersHelper` and the attribute names `agent_id` / `parent_agent_id` on telemetry are taken from the ticket and my reading of the Claude Code documentation; I could not verify them against a live session (live run NOT RUN per #360). If the real setting differs, the CLI test's one assertion on it changes, not the receiver.
- The ticket also says to "feed them to the retro report"; no test covers it, and the ledger is in memory. If cost must survive an engine restart or reach `scripts/retro`, that needs a persistence decision (a small SQLite table next to the evidence store is the obvious default) and a follow-up ticket; I did not cut one.
- `--otel` on top of an existing different `OTEL_EXPORTER_OTLP_ENDPOINT` (the user's own collector): the default I would take is overwrite after confirmation with the change visible in the diff; untested.
- Duplicate OTLP delivery cannot be detected (no request IDs), so a retried export would double count; accepted for deltas.
