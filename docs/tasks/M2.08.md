## Decisions and guarantees

- **Docs checked** (Claude Code settings and hooks reference):
  - The command hook field is `async: true`.
  - An omitted `matcher` matches every occurrence, for tool events and others alike, so no matcher is written.
  - Command hooks without `args` run as `sh -c` on macOS and Linux.
  - The user file is `$CLAUDE_CONFIG_DIR/settings.json` when that variable is set, else `~/.claude/settings.json`.
  - `.claude/settings.json` is the shared file meant to be committed; `.claude/settings.local.json` is personal. Both are loaded by default, and Claude Code reloads settings files when they change.
- **Project scope writes `.claude/settings.local.json`** (#190 D1). The hook command holds machine paths that must not be committed. Claude Code git-ignores that file only when it creates it, so install prints a `.gitignore` note.
- **Shim location:** install copies the shim to `<home>/hooks/taskville-claude-code-shim.sh` (directory 0700, file 0755), atomically, and refuses a symlinked home, hooks directory, or target. The installed path then survives package moves and reinstalls, and a reinstall refreshes the copy. The distinctive name is part of how entries are recognized.
- **Hook command:** `[TASKVILLE_HOME='<home>'] [TASKVILLE_URL='<url>'] '<shim>'`, each part POSIX single-quoted.
  - `TASKVILLE_HOME` is set only when the home is not `$HOME/.taskville`.
  - `TASKVILLE_URL` is set only when the URL is not `http://127.0.0.1:4807`. It comes from `--url`, then `$TASKVILLE_URL`, then config.json's `port`.
  - Only the loopback forms the shim accepts are allowed; anything else is refused.
  - A home with spaces, quotes and `$` is tested by running the exact command under `/bin/sh -c`.
- **Recognizing entries:** a handler is Taskville's only if it is `type: "command"` and its command matches exactly what install generates, ending in the quoted shim path. Uninstall never removes by position, and edited look-alikes are left alone.
- **Writing settings:**
  - The file is parsed as strict JSON. A malformed or empty file, a non-object, or a `hooks` with the wrong shape is refused and left untouched.
  - Unknown keys, other tools' hooks, and key order are kept. JSON keys are written with own-property definitions, so `__proto__` stays a plain key.
  - The file keeps its own indent. The write is atomic (an `O_EXCL` temp file in the same directory, `fchmod` to the old mode or 0600 for a new file, fsync, rename).
  - The file is read again after confirmation; if it changed meanwhile, nothing is written.
- **Symlinks** (#190 D2): user scope follows a symlinked `settings.json`, as dotfiles setups use, and writes the target in place, so the link survives. Project scope refuses a symlinked `.claude` directory or file, because a cloned repository could aim it elsewhere.
- **Backup:** the first install writes `<settings>.taskville-backup` with the original bytes and mode, or an empty file when no settings file existed. Uninstall deletes the backup.
- **What uninstall guarantees:**
  - If nothing but Taskville's entries changed since install, the file is restored byte for byte, or removed if install created it.
  - Otherwise, only Taskville's entries are removed. Matcher groups, events, or `hooks` left empty are dropped, and the file is rewritten with its own indent. JSON that round-trips differently (escapes, number forms, integer-like keys) may be reformatted, and the diff shows that before anything is written.
  - The shim copy is left in place, because another scope may still use it.
- **Diff and confirmation:**
  - A line diff with three lines of context. Every printed line goes through the redaction module, so a token anywhere in the settings file is never printed, even as context. The hook command contains no token: the shim reads `<home>/token` itself.
  - The command asks y/N on a terminal. `--yes` is for scripted use and still prints the diff. `--dry-run` writes nothing.
  - With stdin not a terminal and no `--yes`, nothing is written (exit 1).
  - Running the command again when everything is already in place reports "already installed" and changes nothing.
- **HOME safety:** install and uninstall take HOME only from the environment, never from `os.homedir()`. They refuse when it is unset, unless `--home` or `CLAUDE_CONFIG_DIR` supplies what is needed.

## Lessons

- With hooks, the reliable way to undo an install is the backup, not a structural edit. JSON round-trips are not byte-stable, so "uninstall restores the original" has to be defined (identical when nothing else changed) and tested with deliberately odd formatting.
- A CLI that edits user config should take HOME only from its injected environment. Then tests are safe by construction, and a guard on the real file's mtime proves it.
