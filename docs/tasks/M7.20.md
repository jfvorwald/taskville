- **Review outcome:** see PR
- **Lessons:**
  - Cause: the hop is a one-shot 450 ms animation keyed to `performance.now`, started (with lift 0) by the first main draw that sees the hover. The test needed a second `waitFor` draw within 450 ms. With software WebGL (SwiftShader) sharing a loaded CPU, the first draws after mount came 600 ms or more apart, the hop ended unseen and never restarts, so every later poll read y = 0. CI (a quiet Linux runner) keeps the draws close together. Not a source bug.
  - Fix: the lift and unmount-cleanup tests draw with `performance.now` pinned (0, 200, 700 ms) via `drawAt`/`drawMidHop`, so the hop's timing is set by the test, not the wall clock.
  - Wall-clock one-shot animations cannot be polled with `waitFor` on shared CPUs; pin the clock the code reads.
