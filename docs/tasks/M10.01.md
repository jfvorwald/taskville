- **Root cause:** rows measured before their evidence bodies arrive grow in a later commit. LiveFeed re-measured only unmeasured rows, and the virtualizer's ResizeObserver repositions rows in a React render after paint, so one painted frame drew rows at stale offsets (162 px overlap in the real app; the lead's screenshot caught that frame). Separately, the virtualizer skips scroll compensation for a re-measured row above the view for 150 ms after an upward scroll.
- **Fix:** LiveFeed observes its rows and commits new offsets with flushSync inside the observer callback, before paint; a shouldAdjustScrollPositionOnItemSizeChange hook compensates any row wholly above the view. The scroller is still the nearest scrolling ancestor, so M10.03 (tab slot scrolls) needs no change here. Review fix (roborev 7507): when a row above the view and the partly visible first row resize in one observer delivery, the first resize moved the scroll offset while cached row positions stayed stale, so the second was compensated by mistake (the anchor moved by its growth, 160 px in the test). The adjustment hook now refreshes measurements and judges each row by its current position.
- **Lessons:** layout tests that poll until rows settle cannot see a one-frame overlap. Check layout at paint time (a fresh ResizeObserver created each frame), and drive updates outside act(), which flushes the observer's follow-up render before paint. The investigation was run by the debugger after the test-writer could not reproduce it in component tests.
