## Design

- Migration V2: `checkpoints(project_id, sequence, reducer_version, state_hash, state_json)`, STRICT, PK (project_id, sequence). Accessors in `apps/engine/src/storage/checkpoints.ts` (`storage.checkpoints()`).
- `apps/engine/src/timelines/checkpoints.ts`: `CHECKPOINT_INTERVAL = 500`, `stateAtSequence`. Prunes (SQL, constant time per row) rows of another reducer version, beyond the head, or whose text does not start with `{`; loads the nearest candidate at or before the target and trusts it only if the version matches, the JSON parses, and `stateHash` matches; otherwise deletes it and tries the next lower. Replays the rest and writes the missing multiples of the interval it passed. Cache upkeep (prune, delete, write) is best effort: if another connection holds the write lock the read still answers from the log.
- Route change (named per the lead's approval): `GET /v1/timelines/:id/state` in `apps/engine/src/timelines/routes.ts` calls `stateAtSequence` instead of `replay(eventsUpTo)`. The head shortcut is unchanged.
- Only rows a seek would use get the full hash check; rows beyond the target get the constant-time shape check, so a well-formed forged row beyond the target is verified when a seek reaches it.

## Write policy: lazy

Lazy (on read), so ingest is untouched. The test contract (checkpoints exist at multiples up to the position read, not beyond) also pins it.

## Why the target is missed, and the decision

Lazy means the first seek into a region nobody has seen pays for a replay from the last checkpoint plus serializing every checkpoint it passes (about 1 s at 75 to 90 percent on this loaded machine); every later seek is 0.3 to 50 ms. Meeting the 300 ms p95 for a first seek needs the checkpoints to exist before the user seeks: written on ingest commit (the ingest pipeline is outside this ticket's Owns) or by a background backfill at boot. The seek harness also seeds with `seedLog`, which bypasses ingest, so it would need a warm-up step either way. Default proposal: write on ingest commit when the head crosses a multiple of 500, and backfill lazily for existing logs. No tuning attempted beyond the two measurements.
