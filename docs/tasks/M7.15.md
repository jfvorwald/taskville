## Rule (debugger round, roborev job 7011)

Live events apply in arrival order, unchanged (ARCHITECTURE.md 7.3). A late event changes a piece of state only if it is not older than that state's own time:

| State | Its time | Late event older than it |
|-------|----------|--------------------------|
| open request | `openedAt` | does not close it |
| session activity | `activity.since` | does not replace it |
| open session | `activity.since` | `session.ended` does not end it (new) |
| running tool call | `startedAt` | a boundary does not close it |
| the agent's kept finished call | `finishedAt` | a late finish or boundary does not replace it; the older call leaves the projection (new, finding 3) |
| `lastTurn`, `lastTurnAt`, `consecutiveToolFailures` | none of their own, so the agent's `lastSeenAt` before the event | does not set or clear the turn, does not move the streak (new, finding 2) |

A late event still appends to the log, widens the agent's seen times, counts its tool call, and applies in full where nothing newer is held (tested). `lastTurnAt` goes back to main's meaning (the time of the current `lastTurn`, cleared with it), which removes the crew snapshot and CLI golden line the first roborev round added. REDUCER_VERSION 7 to 8 (finding 1): the engine already rebuilds projections and prunes checkpoints on a version mismatch (`apps/engine/test/storage/projections.test.ts` "rebuilds only projects whose projection is missing, stale, or behind" and "carries a reducer version change across a restart"). Pinned snapshots change only `reducerVersion`. `packages/domain/src/reducer/index.ts` and the three prefix-pin tests are outside Owns, but the version bump requires them.

Known limit: a late `turn_failed` older than a live tool start for the same agent is dropped, although in time order the failure would survive that tool start. This is the conservative side: a stale late event never raises attention for an agent that has newer recorded events (8.1).
