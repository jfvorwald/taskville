# A1.03: Codex permission forwarder shim tests flake under full-suite load (#511)

- **Result:** done
- **PR:** TBD · **roborev:** TBD
- **Checks run:** `npx vitest run --project @taskville/cli apps/cli/test/shim/codex-shim.test.ts` 20 consecutive times under 8 CPU burners: 20 of 20 passed, 48 of 48 each. `pnpm --filter @taskville/cli test`: first run failed (failing test not captured), rerun once alone passed 703 of 703 in 40 files; logged as a flake. `pnpm run lint` exit 0 (existing warnings only). `pnpm run typecheck` exit 0.
- **NOT RUN:** `pnpm check` and the full suite (once per wave).
- **Measurements:** under 8 CPU burners, before the fix 6 of 10 file runs failed (all request-count mismatches), after the fix 20 of 20 passed. A bare loopback listener received `GET /` (user agent `node`, no auth) 1.9 s after opening, while T3 Code was running.
- **Decisions needed:** none
- **Review outcome:** TBD
- **Root cause:** the forwarder tests hand-rolled a fake engine that recorded every request. A local desktop app probes newly opened loopback ports with `GET /` about every 3 s; a probe landing inside a test made the request count off by one, more often under load because tests run longer. The shared `startServer` harness already ignores non-curl clients (M4.12); this listener did not.
- **Fix (test only):** the listener answers non-curl requests with 404 and does not record them, the same rule as the harness. The forwarder only uses curl with `-q`, so its user agent is fixed and real traffic is still counted. The forwarder and the answer-shape rule are unchanged.
- **Lessons:** tests that count requests on a loopback listener must ignore foreign clients; new listeners in shim tests should reuse the harness filter. Investigation by the debugger.
