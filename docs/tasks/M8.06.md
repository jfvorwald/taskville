- `apps/engine/src/http/errors.ts`: the new codes in the `ErrorCode` union (inside Owns).
- `apps/engine/src/evidence/store.ts` (review-fix round, lead-approved): archive-scoped evidence. `store(projectId, items, archiveId?)` and `get(projectId, toolCallId, archiveId?)` key the existing tables by a scope (`projectId` for live, `projectId + "\0archive\0" + archiveId` for an archive), so no schema change; archive bodies do not count against or evict live bodies, never shadow live pointers, and `deleteProject` removes both. Live behavior is unchanged when `archiveId` is absent.

## API surface for M8.07 and M8.08

- Storage (`import { type SqliteArchives } from "apps/engine/src/storage/index.ts"`; `storage.archives()`): `create`, `get`, `running`, `complete`, `fail`, `cancel`, `failInterrupted`, `listDone` (newest first, `created_at` then insertion order), `events(id, from, to)` (inclusive, position order), `eventAt(id, position)`, `positionAtOrBefore(id, at)` (greatest position with occurredAt at or before `at`, compared as instants; 0 if none). `ArchiveRecord`: `id, projectId, kind, label, root, status, createdAt, finishedAt, counts, error, eventCount, firstAt, lastAt` (nulls when unset). `firstAt` and `lastAt` keep the source's timestamp text. Events come back as `StoredEnvelope`s whose `ingestSequence` is the archive position.
- Schema: migration 4 (`LATEST_SCHEMA_VERSION` is 4) adds `archives` and `archive_events` (extra column `occurred_ms`, the instant, indexed with the archive).
- Jobs (`apps/engine/src/importers/index.ts`): `new ImportJobs({ storage, importers, evidence?, now?, maxEvents?, logger? })` with `start`, `status`, `settled`, `close`; `ImportRefusal` with `.code` (`unknown_import_kind`, `unknown_project`, `root_not_configured`, `import_running`). To wire an importer, add it to the `importers` array in `serve.ts` (one line each for M8.01 and M8.02). Error codes on a failed archive: `importer_failed`, `write_failed`, `interrupted`; messages never carry source text.
- HTTP: `POST /v1/imports` (CLI token) answers `202 { importId, archiveId, status: "running" }`; `GET /v1/imports/:id` (CLI token or paired session) answers `ImportStatus`. Errors: `400 bad_request`, `400 unknown_import_kind`, `400 root_not_configured`, `404 unknown_project`, `409 import_running`, `403 credential_not_allowed`, `404 not_found`.
- Protocol (`packages/protocol/src/api.ts`): `importRequestSchema`, `importCountsSchema`, `importStartedSchema`, `importStatusSchema`, `IMPORT_STATUSES`, and the three API error codes.
- Runner behavior to rely on: the event cap is 200,000 (the first N kept, the rest skipped, `counts.truncated: true`); `counts.malformedByCode` is present when the runner rejected events; repeated `(sourceId, sourceEventId)` are skipped keeping the first; evidence is written to the evidence store after the archive completes, scoped to the archive (a failed or cancelled import leaves none); `ImportRefusal` also has `engine_closing` (503).
